# Подключение инея после перезапуска Unreal

Причина возврата прежнего вида: материалы были сохранены, но изменения `MCIceEvent` были применены только через Live Coding. Основная `Binaries/Win64/UnrealEditor-MessControl.dll` оставалась версией от утра 9 октября. Новый процесс Unreal загрузил эту DLL: у CDO `FrozenTongue` был материал `/Engine/EngineDebugMaterials/VertexColorMaterial`, несмотря на сохранённые параметры `M_TongueFrost` (Frost Fill=1, Warm Fade Width=45).

Исправление: редактор корректно закрыт при отсутствии несохранённых пакетов, затем выполнена обычная инкрементальная сборка `MessControlEditor Win64 Development` через `Tools/Build.ps1`. Это обновило основную DLL; сборка завершилась успешно. После запуска нового процесса подключение проверено без Live Coding: CDO назначает `/Game/Gameplay/Cold/Frost/M_TongueFrost`, а материал персонажа — `/Game/Gameplay/Cold/M_PlayerIceCoating`.

Хеш файла `M_TongueFrost.uasset` до и после перезапуска совпадает. Сам материал не потерялся и не переавторивался. Положение камеры редактора восстановлено; временная конфигурация сборки возвращена к исходной.

Короткая проверка в PIE после настоящего перезапуска подтвердила частичное/полное проявление, Frost Fill=1, Warm Fade Width=45, смену тёплых кругов и удаление покрытия. `PreviewVerification.json`: passed=true. `TongueFrost_full.png` показывает актуальный эффект после загрузки основной DLL.

Доказательства: `Inspection.json`, `EditorBuild.log`, `RestartVerification.json`, `PreviewVerification.json`. Первая попытка игрового предпросмотра записывала служебный файл в прежний каталог из-за ошибки пути в обёртке; после исправления пути проверка выполнена успешно. Сам материал, основной модуль и игровые данные этой ошибкой не менялись.

Cook и package не запускались. Бинарная версия до исправления сохранена как `UnrealEditor-MessControl.Before.dll` только для восстановления.
