# Как новый визуал подключён к механикам

Коллега делает модели, материалы и композицию. Игровые компоненты связывают этот визуал с уходом, физикой и правилами забега.

В `L_Mouth` сохранены **10 нижних зубов**: **четыре передних с каждой стороны — игровые**, по одному дальнему — декорации. Восемь игровых зубов являются запасом возрождений. Два дальних в этот запас не входят.

## Что появилось и для чего

| Где искать | Назначение |
| --- | --- |
| Outliner → `Gameplay/ArenaTeeth` → `ARENA / Tooth 01…08` | Восемь отдельных маркеров. В Play каждый заменяется сетевым зубом с налётом, здоровьем, расшатыванием и выпадением. Возрождение скрывает конкретный зуб. ID идут от передних к дальним, попеременно слева/справа. |
| `Art/ArenaDecoration` → `ART / Far tooth Left/Right` | Два дальних зуба: видимые препятствия, без ухода и расходования на жизнь. |
| `Content/Gameplay/Arena/SM_ArenaTooth_*` | Отдельные зубы, выделенные из объединённого ряда коллеги. Форма и UV сохранены; левый ряд использует заранее зеркальные меши. |
| `Content/Gameplay/Arena/M_ArenaToothArt` | Копия эмали коллеги с добавленным налётом, трещинами и вспышкой удара. Остальные входы шейдера сохранены. Выбирается в `DA_ArenaTooth → Gameplay Material`. |
| `Gameplay/Collision` → `COLLISION / Artist mouth` | Скрытая неподвижная оболочка рта с коллизией по треугольникам, без языка. |
| `Gameplay/Tongue` → `GAMEPLAY / Moving tongue` | Видимый язык и его изменяющаяся коллизия. [Движение и волна боли](Tongue.md). |
| `Gameplay/Exits` → `GAMEPLAY / Throat` | Объём удаления еды. Сюда направляется слив кофе. Щётки не принимает. |
| `Gameplay/Exits` → `GAMEPLAY / Brush exit` | Объём выбрасывания щёток за передним краем. Еду не засчитывает. |

Модели `Content/Art/Meshes/Arena/SM_Location`, `SM_Location_teeth` и исходный `M_Enamel` остаются ресурсами художника. Изменения сделаны в карте и отдельных производных ассетах.

Пятна и язвы получают положение и наклон от физической поверхности. В `DA_Day01` появились центр и размеры области воды; в `DA_CoffeeWater` — нижняя отметка `Dry Height`. Она расположена ниже языка, поэтому после слива кофе не остаётся висящей плоскостью. Низ струи находит пол под собой.

## Что менять при следующем обновлении моделей

Отдельный зуб удобнее прислать отдельным мешем. Его можно назначить в `Preview` нужного маркера и подогнать положение; ID и игровые правила сохраняются. Для нового материала нужно перенести три параметра `Coffee`, `Damage`, `HitFlash` в его игровую копию. Нельзя просто заменить материал на чистую эмаль: логика останется, но статусы не будут видны.

После изменения формы языка обновляется производная коллизия и проверяются точки старта, пятна, доступ к зубам, глотка и границы кофе. Это необходимая адаптация: жидкость использует управляемую поверхность и игровые силы, а не автоматическое заполнение любой геометрии.

`ArtSource/ArenaGameplay/ArenaTeeth.blend` содержит выделенные зубы. `teeth.json` хранит исходные центры, `layout.json` — размещение в карте. Скрипты `export_arena_for_gameplay.py` → `prepare_arena_teeth.py` → `integrate_artist_arena.py` воспроизводят именно эту миграцию из двух исходных рядов. Повторный запуск интегратора сохраняет уже размещённые маркеры; это не универсальный автоимпорт будущих изменений.

## Как проверить самому

1. Открыть `L_Mouth`, Play, **F3 → кофейный налёт**: статусы появляются на восьми передних зубах; дальние остаются чистыми.
2. Поднять щётку, удерживать ЛКМ у зуба: налёт снимается по контактам. E лечит/закрепляет повреждённый игровой зуб.
3. В F3 вызвать гибель: запас уменьшается **8 → 7**, из ряда исчезает один конкретный зуб.
4. Запустить завтрак и перетащить еду в глотку; щётку бросить за передний край через Q.
5. Запустить кофе: зацепиться E возле игрового зуба, отпустить и подгребать WASD; дождаться слива.

`Tools/Unreal/verify_artist_arena.py` проверяет сохранённую карту: 8 + 2 зуба, расположение дальних, отдельные выходы и пять трассировок реального пола. Сетевые сценарии запускаются через `Tools/Test.ps1`.

Оболочка рта использует подробную статическую коллизию, язык — изменяемую треугольную поверхность, а зубы — простые объёмы. Для готового арта их можно оптимизировать отдельно. IK рук и баланс плавания против слива остаются отдельными задачами.
