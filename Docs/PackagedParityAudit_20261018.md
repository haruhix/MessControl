## Ice-specific dependency: tongue CPU geometry confirmed in the Editor

Ice is not just a shader assignment. `MCTongue::RebuildSurface()` extracts LOD 0 / section 0 CPU geometry from `SourceMesh`; ice start requires a tongue with nonempty vertices, and frost copies its procedural section. Empty tongue geometry can therefore stop the event or remove frost even when every ice material was cooked. Source: [MCTongue.cpp:49](E:/DEVGAME/MessControl/Source/MessControl/Private/MCTongue.cpp:49), [MCIceEvent.cpp:172](E:/DEVGAME/MessControl/Source/MessControl/Private/MCIceEvent.cpp:172), [1437](E:/DEVGAME/MessControl/Source/MessControl/Private/MCIceEvent.cpp:1437).

The installed UE 5.8 implementation explicitly requires `UStaticMesh::bAllowCPUAccess` for this extraction in cooked builds: [KismetProceduralMeshLibrary.cpp:458](E:/UE/UE_5.8/Engine/Plugins/Runtime/ProceduralMeshComponent/Source/ProceduralMeshComponent/Private/KismetProceduralMeshLibrary.cpp:458).

The inspection was outside PIE and reported no dirty map or content packages. Source: [LiveInspection.json](E:/DEVGAME/MessControl/Saved/Feedback5_11_20261018/LiveInspection.json).

This confirms the actual current assignment and CPU-access prerequisite, rather than inferring it from the historical catalog or the older non-V10 mesh. It also matches the author's explicit setup in [integrate_arena_v10.py:159](E:/DEVGAME/MessControl/Tools/Unreal/integrate_arena_v10.py:159). **No current CPU-access defect was found.** The live section count is Editor evidence; successful extraction and frost rendering from cooked payloads still require a packaged-client check.
