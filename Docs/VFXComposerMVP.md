# VFX Composer — история прототипов

> Текущий публичный маршрут — **Tools → Wash n Smash → VFX Composer / `MC.VFXComposer`**: единый shared-каталог контекстов и слоёв. Отдельные окна Elements/Layers/Perk Action Preview сняты с маршрута; совместимые входы перенаправляются в новое окно, данные сохранены. Ниже описаны предыдущие прототипы и их проверки. Новая runtime-композиция независимых NS и дополнительные контексты ещё проходят реализацию/проверку; строгий single-NS экспорт теперь отдельная дополнительная операция. Начинать работу следует с [актуального гайда](../Tools/VFXGuide/index.html#composer), статусы — в [checkpoint](Validation/ComposerActionWorkspace_20261031.md).

## Текущий маршрут · 31.10.2026

**Tools → Wash n Smash → VFX Composer** и команда **`MC.VFXComposer`** теперь открывают новый редактор элементов: preview слева, свободный граф/библиотека в центре, настройки выбранного элемента либо Output справа. Прежняя панель списка слоёв и таймлайна сохранена через **Tools → Wash n Smash → VFX Layers** / **`MC.VFXLayers`**.

Реализованы произвольные NS-элементы (до 32), стабильные GUID, перемещение узлов, выбор нескольких, clone/delete, группы, Solo/включение, реальные thumbnail, библиотека с фильтрами, Undo и сохранение нового master-preset с layout. Это граф композиции NS; он не является внутренним Niagara dataflow graph и не обещает весь функционал Fab.

Для полного действия: **Perk Action Preview / `MC.PerkVFXPreview` → ракетница → событие → «Собрать эффект в Composer…»**. Контекстная левая область использует тот же настоящий runner с анимацией и физическими руками. **«Проверить в действии»** собирает поддержанный временный результат и подменяет только событие в копии профиля. Остальные активки и пассивные сценарии ещё не подключены.

Путь сохранения: **новый постоянный master-preset → проверка строгого экспорта → новая NS → явное назначение событию рабочей копии → сохранение нового профиля → отдельное назначение профиля в DT**. Начальные папки: `/Game/Tests/VFXPractice/Recipes`, `/Generated`, `/Profiles` под тем же VFXPractice. Источники не перезаписываются. Editor-only provenance результата восстанавливает master с его элементами/группами; внешние настройки события сохраняются отдельно и проверяются на совместимость.

Художественные ручки читаются из настоящих User inputs: Float, Linear Color, Vector3, Bool. Int/Position/DI/object и придуманные SpawnCount/Lifetime/Emissive поля не становятся рабочими только от похожей подписи. Масштаб transform меняет весь элемент; ParticleScale — отдельный input, если он имеется.

**Duration/Tail — окно и максимальный хвост изолированного preview.** Экспорт сохраняет native Niagara timing; он не запекает мировую отсечку по Duration. Solo не ограничивает экспорт. При action-preview жизненным циклом Loop управляет действие.

Single-NS builder работает со строгим проверяемым поднабором. Кандидаты находятся в ActiveSkills/VFX, VFXPractice/Effects и двух исследовательских коллекциях; сам путь не гарантирует поддержку. Несовместимые SystemState/inputs/rapid-iteration, неподдержанные внешние зависимости/DI/events/stages, отсутствие GPU fixed bounds, per-layer transform, socket/смешанные привязки и незапекаемые emission cutoffs или continuous delay отклоняются с причиной. Общие шесть gameplay inputs должны совпадать по типам и значениям. Это не произвольный merge любых NS.

**Core UI / Build08 подтверждён частично:** JSON фиксируют clone с новым GUID, save/reopen, отказ overwrite, совместное перемещение узлов, group roundtrip/Undo, новую NS с provenance и apply только к рабочему профилю без изменения DT. Проверены отказы для transform, конфликтующих shared inputs и неподдержанного источника. Readback шести generated emitters не доказал визуальную эквивалентность: `Fidelity09_ReadOnly.json` сохраняет rejected diagnostic и открытые runtime/renderer вопросы. **Основной repeat Loop Build11 прошёл ограниченную функциональную проверку: шесть native-циклов примерно за 28 с, один cached generated System и максимум 5 Niagara-компонентов без наблюдаемого роста. Арт/fidelity impact остаётся pending. Live Gallery frontend исправлен в Build12: показаны selectable STileView cards/search/category counts; проба NS_Practice_Trail прошла ≈16 с/4 hero runs без изменения рецепта, max components 5. Native-пауза Pause11 сохранила точное время. Читаемость эффекта, арт, весь каталог и readiness остаются открытыми.** Сводка: [PerkActionPreview_20261031.json](Validation/PerkActionPreview_20261031.json). Файлы и границы: [матрица приёмки](Validation/ComposerAcceptance_20261031.md). Исторические тесты ниже относятся к старому слоевому backend, а не всей новой связке authoring → export → perk. Художественного аппрува, полной Fab parity и шести готовых perk adapters нет. Подробный маршрут: [PerkActionPreview.md](PerkActionPreview.md).

### Уточнение диагностики: скрытый владелец preview · Build12

Основной агент доказал конкретную причину невидимости контрольного VFX в редакторе: `ProbeRender12.json` показывает активный/видимый/зарегистрированный NiagaraComponent с 4326 CPU-частицами исходной `/Game/NiagaraExamples/FX_Explosions/NS_Explosion`, но его transient-владелец `WorldSettings` имеет `is_hidden_ed=true` и `is_temporarily_hidden_in_editor=true`. Рецепт `unhide_preview_vfx12.py` изменил только временную editor-видимость WorldSettings отдельного preview world. `OwnerVisibilityAB12.json` фиксирует true → false; основной агент увидел взрыв **на том же остановленном кадре** (`PreviewOwnerVisible12.png`), без изменения исходника или алгоритма частиц.

Это доказанный дефект инструмента предпросмотра. Прежние пустые/слабые кадры сохраняются как диагностика, но по ним нельзя приписывать отсутствие картинки художественному качеству эффекта. Постоянная scoped-правка выполнена в обоих preview-scene constructors; Build13 успешен за 28,25 с. `Visibility13.json` и `FinalState13.json` подтверждают fresh constructor owners native/standalone с hidden_ed=false и temporarily_hidden=false, без live workaround. Основной агент лично просмотрел свежий contact sheet/запись: выбор stock NS_Explosion, native Rocket и видимые orange burst/smoke/tail, около трёх циклов за 12 с. Это приёмка демонстрации ИНСТРУМЕНТА на существующем stock effect, не художественное одобрение наших VFX или полная source/generated equivalence. ## История: панель слоёв `MC.VFXLayers` · 30.10.2026

Статус на 2026-10-30: первая версия собрана для Unreal Engine 5.8.1 и открыта в настоящем Editor. Итоговый Build05 успешен за 12,46 с; первый полный проход Build01 занял 124,31 с. Три native-проверки Composer прошли в Native02: ParameterIsolation, ScheduleAndSnapshot, Validation (без ошибок/предупреждений этих тестов). Реальный UI создал новую DA через диалог после дублирования, Undo/Redo и удаления слоя. Основной агент осмотрел реальную запись слоёв и затухания, текущего зубика при исправленном свете и боковой ракурс без обрезания. Первые пересвеченный preview и ошибка тестовой фикстуры сохранены как диагностика, не принятые превью. Эти результаты не означают художественного принятия эффектов, проверки всех кнопок или готовности интеграции с абилками.

Это локальный инструмент MessControl для композиции из существующих Niagara Systems. Он не копирует сторонний VFX Composer, его код или библиотеку эффектов. Исходные NS остаются редактируемыми в стандартном Niagara Editor.

Требование от 31.10.2026 расширило цель до **предпросмотра полного действия каждого перка с анимацией и отдельными VFX-слотами событий**. Первый вертикальный проход ракетницы и новый редактор элементов описаны выше; исходный контракт: [VFXActionPreviewContract.md](VFXActionPreviewContract.md).

## Что входит

- Native Slate-вкладка `VFX Composer · Wash n Smash` и отдельный изолированный preview world с нашим зубиком в неподвижной исходной позе. Окно не запускает PIE и не изменяет текущий уровень.
- 1–32 слоя: добавить выбранные в Content Browser NS, дублировать, удалить, поменять порядок, включить/выключить, Solo для просмотра.
- Настройка выбранного слоя через Details: Niagara System, Transform, привязка, socket, начало, длительность эмиссии и поддерживаемые User-параметры. Инспектор работает с независимой копией структуры; завершённая правка переносится в рабочую композицию отдельной Undo-транзакцией. Общие Duration / Tail вынесены в верхнюю панель.
- Нижний таймлайн показывает эмиссию каждого слоя, хвост и реальную позицию воспроизведения. Это обзор времени композиции, не редактор внутреннего Niagara graph.
- Play, Pause, Reset, поиск времени, движение подопытного, пол, границы, фокус и готовые ракурсы спереди/сбоку/сзади. Preview ждёт завершения известных компиляций Niagara и материалов до запуска таймера; это editor-проверка, не сертификация packaged PSO.
- Открытие существующей DA только как временной независимой копии. Сохранение всегда создаёт **новую DA**, существующие DA и NS не перезаписываются.
- Undo/Redo для изменений рабочей композиции и запрос Save / Discard / Cancel при обычном закрытии или замене рабочей копии.
- Валидация структуры и активных User-переопределений до сохранения.

Эта историческая панель доступна через **Tools → Wash n Smash → VFX Layers** или консольную команду `MC.VFXLayers`. Native-модальные окна сохранения могут блокировать последовательное выполнение MCP-команд до закрытия диалога; при первой проверке диалог закрывался через Computer Use. Базовая папка старых композиций: `/Game/Tests/VFXPractice/Compositions`. Их открытие в новом Composer импортирует данные в рабочую копию; для экспорта нужно явно сохранить новый master-preset.

## Первый проход

1. Выбрать одну или несколько **Niagara Systems** в Content Browser. Нажать `+ Выбранные Niagara`.
2. Выбрать слой слева. Справа появятся настройки именно этого слоя; общий массив `Layers` вручную раскрывать не нужно.
3. Установить `Binding`: `Composition` — привязка к началу композиции; `World` — оставить компонент в мировой точке запуска; `Subject` — привязать к компоненту зубика или его socket.
4. Выставить Transform, `StartSeconds`, `EmissionSeconds`. Нулевое `EmissionSeconds` означает эмиссию до конца основной части композиции. Время жизни уже рождённых частиц определяется самой Niagara.
5. Нажать `Найти User-параметры слоя`. В найденном параметре включить `bOverride`, затем изменить значение. Поддержаны Float, Linear Color, Vector3 и Bool. Position, Int, объекты, массивы и Data Interfaces пока не имеют авторского интерфейса в этом инструменте. Пропущенные типы перечисляются в сообщении.
6. Проверить последовательность через Play / Pause / Reset. Ползунок пересчитывает симуляцию после отпускания, чтобы не выполнять тяжёлый replay на каждом пикселе перемещения. Числовое поле времени позволяет перейти в точный момент.
7. Сравнить результат без Solo и из игрового ракурса после будущей интеграции. Выбрать `Сохранить новую DA…`, прочитать ошибки, если сохранение заблокировано.

Открытие кнопкой `Открыть исходную Niagara` запускает обычный Niagara Editor. Изменения в **том** редакторе являются отдельным явным редактированием исходной NS; Composer автоматически их не сохраняет.

## Какие роли можно проверить сейчас

| Роль | Как просматривать | Ограничение |
|---|---|---|
| Вспышка в точке | World + короткая эмиссия | Урон и столкновения отсутствуют |
| Эффект на зубике/socket | Subject + нужный socket | Нет автоматического mesh-sampling DI |
| Эффект вокруг общей опоры | Composition + Transform | Не является самостоятельной игровой абилкой |
| След при движении | Subject + `Движение` | Только движение исходного меша, без игровой анимации и физики |

Это начальная часть библиотеки паттернов. Полноценные projectile → impact, луч/связь двух целей, сэмплирование поверхности меша, движущаяся зона, ручной preview события попадания и привязка к полному действию персонажа требуют следующих этапов. Наличие похожего исходного NS не добавляет автоматически эти игровые правила.

## Как использовать результат в игре

`UMCVFXComposition` хранит слои и ссылки на исходные NS. `AMCVFXCompositionActor` предоставляет:

1. `PrepareComposition(Composition, OutError)` — подготовить ресурсы во время загрузки/прогрева.
2. `PlayPrepared(Subject, bHonorSolo=false)` — запустить подготовленную композицию с нужным компонентом-подопытным.
3. `PauseComposition`, `StopComposition` — управление жизненным циклом.

Solo — инструмент просмотра; обычный runtime-вызов его игнорирует. Включённые User-переопределения проверяются по имени **и типу**, затем применяются на отдельный NiagaraComponent слоя. Имя выдуманного параметра само по себе не подключает соответствующую ручку к произвольной Niagara System.

Подключение DA к `DT_Perks` / VFX-профилям и конкретным событиям абилок в этой первой версии не выполнено. Для runtime-использования композиция и её вложенные NS должны быть включены в ресурсы соответствующей локации и прогрев. Source refs в DA сами по себе не подтверждают завершённый shader/PSO readiness.

## Ограничения и приёмка

- Это композиция самостоятельных NS, **не экспорт в единый NS**. Так сохраняются внутренние события, scratchpad-скрипты, User-параметры и настройки исходных систем. Параметры разных слоёв не сталкиваются по именам.
- Каждому слою соответствует отдельный NiagaraComponent; это не оптимизатор draw calls/overdraw. 32 — технический верхний предел, не рекомендуемая художественная норма.
- Порядок слоёв не задаёт порядок прозрачного рендера.
- Seek использует ограниченный replay фиксированными шагами. GPU/history-зависимые эффекты и недетерминированные источники могут отличаться от непрерывного воспроизведения. Нельзя обещать frame-exact scrubbing.
- Preview использует отдельное освещение и исходный меш зубика. Окончательная художественная проверка нужна в игровом освещении, на масштабе игровой камеры и с настоящей анимацией.
- Сам Composer не меняет логику лечения, урона, броска или столкновения. Gameplay остаётся у вызывающего действия.
- Сохраняйте рабочую DA перед закрытием Editor. Горячая выгрузка/перезагрузка Editor-модуля не поддерживается; новые отражённые классы подключаются обычным перезапуском после сборки.
- Задача не включает загрузки/покупки сторонних библиотек и не записывает generated-media в Git.

## Почему не склеивать emitter handles автоматически

Проверено чтением локальных исходников UE5.8.1:

- `UNiagaraSystem::DuplicateEmitterHandle` дублирует emitter и создаёт новый handle/GUID; это не перенос всего исходного System graph.
- Штатный `FNiagaraSystemViewModel::DuplicateEmitters` дополнительно исправляет external scratchpads, перестраивает nodes и переносит User-параметры. Совпадающие имя и тип объединяются; конфликтующие типы требуют переименования.
- Event handlers могут ссылаться на `SourceEmitterID`, Data Interfaces — на имя другого emitter. Универсальный merge должен ремапить эти зависимости.
- Niagara timeline связывает время с module metadata / input binders; у произвольных NS нет общего надёжного поля «сдвиг всего эффекта».

Поэтому в первой версии исходные Niagara Systems запускаются отдельно. Гарантии универсального безопасного merge не заявляются.
