# Редактирование локализации MessControl

Главный каталог — `/Game/Gameplay/UI/Data/DT_UI_Localization`. Одна строка соответствует постоянному ключу, языки видны рядом в отдельных колонках. `Context` объясняет, где показан текст и что означают его параметры.

| Колонка | Язык | UE culture |
|---|---|---|
| `RU` | Русский | `ru` |
| `EN` | Английский | `en` |
| `DE` | Немецкий | `de` |
| `FR` | Французский | `fr` |
| `ES` | Испанский | `es` |
| `ZH_HANS` | Китайский, упрощённое письмо | `zh-Hans` |
| `ZH_HANT` | Китайский, традиционное письмо | `zh-Hant` |
| `JA` | Японский | `ja` |
| `KO` | Корейский | `ko` |
| `PT_BR` | Бразильский португальский | `pt-BR` |

Другие языки и региональные варианты находятся в `AdditionalLanguages`, например `en-GB`, `zh-CN`, `ja-JP` или `es-419`. Точные региональные варианты сохраняются отдельно: перевод `zh-CN` не превращается автоматически в общий `zh-Hans`, а `pt` — в бразильский `pt-BR`. Новые ячейки создаются пустыми; наличие колонки само по себе не означает готовый перевод. Для CJK-текстов необходимо отдельно проверять покрытие шрифтов, переносы и читаемость в реальных виджетах.

## Приоритет языков

Ориентир на 19 октября 2026 года — [Steam Hardware & Software Survey за сентябрь 2026](https://store.steampowered.com/hwsurvey/?l=english): английский 34,20%, упрощённый китайский 31,39%, русский 9,05%, испанский Испании 4,08%, бразильский португальский 3,70%, немецкий 2,48%, японский 2,41%, французский 2,08%, польский 1,49%, корейский 1,37%, традиционный китайский 1,27%, турецкий 1,09%, тайский 0,82%. Это добровольный анонимный опрос и распределение языка клиента Steam, а не доли выручки или покупателей MessControl.

Рабочий приоритет проекта: сначала `RU`, `EN` и `ZH_HANS`; затем существующие `DE`, `FR`, `ES` вместе с `PT_BR`, `JA`, `KO`, `ZH_HANT`. Это наше решение для игры, а не обещание продаж из статистики. Польский, турецкий, тайский и `es-419` оцениваем следующим шагом по региональным wishlist и отклику игроков. [Steamworks рекомендует проверять региональные wishlist после локализации страницы магазина](https://partner.steamgames.com/doc/store/localization).

Статистика определяет приоритет работы, но не заполняет перевод: новые языковые ячейки остаются пустыми до подготовки и проверки копии. Поддержку языка в Steam следует объявлять после готовности соответствующего интерфейса/субтитров/озвучки; перевод страницы магазина и перевод игры — отдельные части.

Текущий этап меняет редактирование каталога и подготавливает языковые колонки, шрифты и ICU-данные. Выбор языка сохраняет существующее поведение UE culture; новый переключатель языка и автоматическое применение языка Steam здесь не добавляются. Это следующий этап после подготовки переводов. Наличие китайской/японской/корейской колонки не означает готовую локализацию, автоматический выбор языка или проверенный запуск перевода в packaged-игре.

В `DT_UI_Cards` и `DT_UI_Boosters` остаются изображения, игровые ID и ссылки `DisplayNameKey` / `DescriptionKey`. Переводы названий и описаний редактируются в общем каталоге:

| Пример ключа | Что переводит |
|---|---|
| `UI.Card.P01.Title` | Название карточки P01 |
| `UI.Card.P01.Description` | Описание карточки P01 |
| `UI.Booster.Fallback_Mouthwash.Title` | Название бустера |
| `UI.HUD.Cleanliness` | Надпись интерфейса |

Имя строки — постоянный ключ. Изменение формулировки в `RU` не требует переименования строки или изменения C++. Изображение карточки и `GameplayPerkID` не зависят от перевода. Пользовательские таблицы и ссылки в теме сохраняются; инструмент миграции не переназначает их на стандартные таблицы.

## Обычная работа в Unreal

1. Открой `DT_UI_Localization` и найди строку по смысловому ключу.
2. Исправь текст в нужной языковой колонке. Пустой перевод использует доступный родительский язык и русскую копию.
3. Сохрани таблицу. Выбери язык в Preview игрового виджета и проверь длину текста, переносы и числовые значения.
4. Для новой строки выбери постоянный ASCII-ключ, заполни `RU` и `Context`, затем укажи ключ в локализуемом элементе интерфейса.

Сохраняй все именованные параметры, например `{Current}`, `{Maximum}`, `{Seconds}`. Их можно переставлять в предложении, но нельзя удалять или переименовывать. Для форм множественного числа используются полные шаблоны Unreal `plural` / `ordinal`; их проверяет native-валидатор. Имена игроков не переводятся.

Старые `SourceText`, `Localizations`, названия и описания в презентационных таблицах сохранены как совместимый запасной вариант. Они скрыты от обычного редактирования. `SourceText` также сохраняет старую формулировку для прежних привязок, поэтому его нельзя автоматически заменять при исправлении `RU`. Новая локализация выбирается по постоянному ключу.

## Работа в Excel или другом редакторе CSV

Используй `Tools/Unreal/UI/author_localization_catalog.py` из Python Console Unreal. Экспорт не меняет игровые ассеты:

```python
import importlib.util
path = 'E:/DEVGAME/MessControl/Tools/Unreal/UI/author_localization_catalog.py'
spec = importlib.util.spec_from_file_location('mc_localization_authoring', path)
catalog = importlib.util.module_from_spec(spec)
spec.loader.exec_module(catalog)
catalog.run('export', csv_file='E:/CodexWork/Localization/Texts_01.csv')
```

Рядом создаётся `Texts_01.csv.baseline.json`. Сохрани оба файла вместе. В CSV видны обычные тексты, а baseline хранит исходные значения и FText-идентичности. Помимо десяти основных колонок дополнительные языки экспортируются отдельными колонками, например `Language:es-419`. Экспорт использует UTF-8 с BOM, запятую как разделитель и стандартное экранирование кавычек/переносов.

После редактирования:

```python
catalog.run('import', csv_file='E:/CodexWork/Localization/Texts_01.csv')
```

Импорт изменяет только отредактированные ячейки. Строки, отсутствующие в частичном CSV, не удаляются. Неизменённые тексты сохраняют исходную FText-идентичность. Если ту же ячейку успели по-разному изменить в Unreal и CSV, импорт останавливается с указанием конфликта. Не переименовывай `Name`, чтобы исправить формулировку; для этого есть `RU` и другие языки.

До записи создаются JSON-снимки и копии пакетов с SHA-256 в `E:/CodexWork/MessControlLocalization_20261019/Authoring/<operation>/Before`. После импорта запускается native-проверка таблиц. Отсутствующие target-таблицы, неподходящий тип строки, повторяющиеся ключи и незагруженная новая C++-схема не принимаются. Несохранённые изменения выбранных таблиц нужно предварительно сохранить; чужие открытые ассеты инструмент не сохраняет.

## Миграция старого набора таблиц

Выполняется один раз после загрузки Editor с новой C++-схемой:

```python
catalog.run('plan')       # Только отчёт и запланированные JSON, без изменения ассетов.
catalog.run('migrate')    # Backup → перенос → native-проверка → сохранение трёх DT.
```

Инструмент читает сохранённые/загруженные строки проекта, а не перезаписывает их стартовыми JSON из репозитория. Переносятся существующие переводы и региональные варианты. Сохраняются игровые ID, произвольные имена строк, изображения, старые поля и неизвестные дополнительные поля. Повторная миграция не отменяет последующие правки централизованных текстов. Новый каталог не генерирует вымышленные переводы: незаполненные языки остаются пустыми.

Чтобы добавить подготовленный набор новых ключей в существующую таблицу, передай его явно:

```python
catalog.run('migrate', additional_rows_file='E:/CodexWork/Localization/NewRows.json')
```

Файл содержит массив строк того же формата. Уже существующие ключи и их правки не заменяются содержимым файла; добавляются только отсутствующие строки. Это позволяет подключить новые тексты главного меню, не перезаписывая переводы сохранённой таблицы стартовыми значениями.

Для пользовательского набора явно передай все три пути:

```python
catalog.run('plan',
    localization_table='/Game/MyUI/DT_Texts',
    card_table='/Game/MyUI/DT_Cards',
    booster_table='/Game/MyUI/DT_Boosters')
```

При совпадении автоматически создаваемого ключа с уже существующим текстом другого смысла миграция останавливается. Для уже заданных `DisplayNameKey` / `DescriptionKey` существующий центральный текст сохраняется. Сам инструмент не меняет ссылки Theme, карты, Blueprint-деревья и игровой баланс.

Проверки чистой миграции/CSV без запуска Unreal:

```powershell
python -m unittest discover -s Tools/Unreal/UI -p test_localization_catalog.py -v
```

Они проверяют сохранность данных, повторяемость, региональные варианты, конфликты и CSV round-trip. Реальные виджеты и смена языка дополнительно проверяются в Editor; успешный перенос данных сам по себе не доказывает корректную вёрстку.
