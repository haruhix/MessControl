**Каталог одежды и примерка**

Одежда хранится в DataTable `/Game/Data/DT_CharacterCosmetics` со структурой `MCCosmeticCatalogRow`. Одна строка — один статический аксессуар. Имя строки служит ID предмета: сохраняй существующие ID, чтобы не потерять связи с владением и экипировкой.

1. Открой таблицу в Content Browser и выбери строку в **Row Editor**. Блок **Fitting Preview** показывает выбранный аксессуар на настоящем скелете персонажа. Изменения `Mesh`, `Materials`, `AttachBone` и `LocalTransform` обновляют примерку до сохранения таблицы.
2. **Frame** или **F** кадрирует тело вместе с аксессуаром; **Front / Side / Back** дают виды спереди, сбоку и сзади. Для остальных ракурсов используй стандартное управление орбитой и приближением viewport Unreal. Селектор внешности над превью меняет только тело для примерки; очистка возвращает внешность из настроек персонажа.
3. Смотри подпись под превью: там показаны ID, слот, крепление, вычисленная цена и проблемы с мешем, материалами, иконкой или данными. Превью строится в отдельном мире редактора, в опорной позе скелета. Оно проверяет посадку статического аксессуара; анимацию персонажа, скиннинг одежды и симуляцию ткани нужно оценивать отдельно в игре.

| Поле | Что задавать |
|---|---|
| Имя строки | Уникальный стабильный ID аксессуара; без переименования уже используемых предметов. |
| `Slot` | Категория экипировки: существующие `Hat`, `Face` или новое осмысленное имя. Один предмет на слот; максимум 16 записей в одной экипировке, а не 16 строк в каталоге. Новые категории берутся из строк таблицы. |
| `Mesh` | Реальный `StaticMesh` аксессуара. Нужна отдельная иконка товара, даже если меш виден в примерке. |
| `AttachBone` | Существующая кость или сокет выбранного тела; для текущих головных аксессуаров — `head_x`. При отсутствующем креплении превью скрывает аксессуар и выводит причину. |
| `bMeshSpaceFit` | Включено: `LocalTransform` задан в координатах исходного меша тела и переводится относительно опорной кости. Выключено: трансформ уже локален к креплению. Не переключай режим без проверки посадки. |
| `LocalTransform` | Положение в сантиметрах Unreal, поворот в градусах в редакторе, масштаб — множитель без единиц (`1` = исходный). Экспорт JSON хранит поворот кватернионом. |
| `Materials` | Переопределения по индексам материальных слотов меша, начиная с `0`. Пустой элемент оставляет материал меша. Используй сохранённые материалы; временные PIE/MID не являются исходниками каталога. |
| `bEnabled` | Доступность предмета в игровых данных. Выключенный предмет можно продолжать редактировать в примерке. |
| `bDefaultUnlocked` | Предмет доступен игроку по умолчанию; это отдельное правило владения, а не скидка. |
| `bUseCanonicalCommerce` | Включает поля продажи из этой строки. Для существующих строк включается контролируемой миграцией. |
| `ShopItemId` | Стабильный ID покупки. `None` использует имя строки. При переносе сохраняется старый ID магазина; он должен быть уникален и не совпадать с ID другого товара. |
| `DisplayName`, `Description` | Резервные тексты `FText`; название и описание должны быть заполнены. |
| `DisplayNameKey`, `DescriptionKey` | Ключи строк общей таблицы локализации; обязательны для канонического товара. |
| `Icon` | Обязательный сохранённый `Texture2D` для карточки товара. Превью посадки не заменяет иконку. |
| `BasePrice` | Базовая цена в целых монетах, от `0`. Нулевая цена — бесплатный товар, но сама по себе не выдаёт владение. |
| `DiscountPercent` | Скидка в целых процентах `0–100`: `25` означает 25%. Итог: `floor(BasePrice × (100 − DiscountPercent) / 100)`. Например, `35` и `20` дают `28` монет. |
| `Rarity` | `Common`, `Rare`, `Epic` или `Legendary`. Редкость сама не задаёт шанс появления и не меняет цену. |
| `bInShop` | Разрешает продажу. Уже купленные доступные предметы остаются выбираемыми, даже если сейчас не продаются. |
| `ShopAppearanceChance` | Вероятность появления на одну ротацию магазина в диапазоне **`0–1`**: `0.1` = 10%, `0` = никогда, `1` = всегда при включённых `bEnabled` и `bInShop`. Это не число процентов: `10` вводить нельзя. Проверка отдельная для каждого предмета; повторное открытие магазина не перебрасывает ту же ротацию. |
| `SortOrder` | Целый приоритет в каталоге предложений магазина; меньшие значения идут раньше. |

Для локализации открой `/Game/Gameplay/UI/Data/DT_UI_Localization`. Создай строки с именами, указанными в двух ключах, и заполни `SourceText`, `RU`, `EN`, `DE`, `FR`, `ES`, `PT_BR`, `ZH_HANS`, `ZH_HANT`, `JA`, `KO`. Для новой одежды можно использовать понятный стабильный шаблон `UI.Clothing.<ID>.Name` и `.Description`; существующие ключи сохраняй. Заголовок дополнительного слота использует `UI.Wardrobe.SlotHeading` с аргументом `{Slot}` — именем категории. Перевод не требует уменьшать шрифт: проверяй длинный текст в адаптивной карточке.

В гардеробе «Без аксессуара» очищает только выбранный слот. Очистка не продаёт предмет и не удаляет владение. Примерка неоплаченного предмета не даёт права сохранить его как купленный. Неполученная одежда вне текущего ассортимента скрыта; купленная доступна для выбора и сохраняет свои канонические подписи и иконку.

При `bUseCanonicalCommerce=false` продажей по-прежнему управляет связанная строка `/Game/Gameplay/Hub/Economy/DT_HubCatalog`. После миграции одежда берёт цену, скидку, копию, иконку, редкость и шанс из `DT_CharacterCosmetics`; старые строки Hub остаются для совместимости, но их независимые поля продажи больше не используются для перенесённой одежды. Совпадающий старый ID продолжает вести к тому же предмету. Если изменить канонический `ShopItemId`, устаревший другой alias не станет вторым предложением. Сохраняй опубликованные ID и не создавай дубликаты.

Миграция существующих десяти предметов сохраняет меши, материалы, посадку, слоты, флаги и ID; переносит текущие предложения и реальные PSD-иконки, ставит скидку `0` и шанс `1`, сохраняя прежнюю доступность. Ключ и исходная строка резервного FText сохраняются при явном присвоении namespace целевого пакета до сохранения Unreal. Полное применение выполняется отдельным инструментом с dry-планом, проверенными резервными копиями и закрытым редактором целевой таблицы; вручную переносить весь JSON поверх открытой строки не нужно.

Эта инструкция описывает контракт исходного кода. Результаты сборки, миграции, примерки, покупки и проверки первого появления ресурсов записываются отдельно в отчёте валидации; документ не заменяет эти проверки.
