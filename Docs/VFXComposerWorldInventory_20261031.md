## Required migration boundaries

- **Boss.Nut.Cues is twenty distinct contexts**, currently sharing seven NS fields plus procedural materials. Shared asset replacement is not per-attack authoring. Preserve hand-cast vs target-impact vs floor telegraph context; use real boss mechanics/animation, not direct cue-only playback.
- Frost danger/safe zones, coffee coverage/flow, throat intake and ground zones have gameplay geometry. Expose appearance and native event frames; never let a cosmetic NS or editable visual move the real protected area.
- Coffee/fog/surface overlays/weapon trails/death shards are partly procedural mesh, MID, MPC or scene components. Fish reward and grill hologram are UMG. A Niagara-only slot is insufficient for “all VFX editable”; keep the same shared Composer with typed presentation bindings.
- Six source hook entries already exist: CleanStain, CleanArenaTooth, RepairArenaTooth, NutEnemyDeath, CharacterDeath, FishingCatch. They are metadata; actual profile binding/context providers remain separate capabilities.
- Existing boss lab has native Tank/Mage/Zombie/Phase3 comparison mechanics and is a useful provider foundation. It is not itself global Composer coverage or another ordinary public entry point.

## Avoid accidental duplicate/legacy activation

- Nut Shield/Melee/HeadSplit specialized presentation returns before generic rendering. Preserve this ownership rather than stacking a new default burst.
- `MCHazardWave.cpp:89–90` selects the actual mint/wave FrostNova component and hides the fallback Ring when frost/tongue presentation owns the wave. Do not re-enable old rings as new layers.
- Shared ReactionVFX legacy/comparison flags and disabled old perk rows do not mean enabled new actions. No deletion/reactivation is justified without saved-reference checks.
- Asset-authoring libraries and geometry helpers are not individual gameplay effects; static UI/theme art is not automatically an animated VFX.

## Proposed order

1. **B1 — independent binding core:** stable shared registry + owner/profile resolution, no DT_Perks dependency for boss/map actions; resource and Apply/Undo contracts.
2. **B2 — ordinary contacts/reactions:** actual tool hit/brush/spray, tooth care, food/enemy/player death. Reuse existing metadata hooks and add real contexts.
3. **B3 — bosses:** nut twenty cues and projectile/fuse/landing contexts, then generic boss hook/BP reconciliation; reuse existing native lab mechanics.
4. **B4 — map/environment:** Ice/FrostNova and safe zones, coffee/storm, fog, cataclysm, throat and hazards. Persistent scene/material/mesh support as well as Niagara.
5. **B5 — hub/rewards:** fishing scene and UMG catch flight, task coins/chest, grill hologram and zones.

Each delivered owner needs discoverability, actual source opening, real scenario, saved-data roundtrip/Undo, interruption/reset, location prewarm and actual short motion review. Catalog metadata alone is not delivery.
