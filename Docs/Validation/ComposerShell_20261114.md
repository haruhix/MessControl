# Composer: первый этап общего нативного UI

## Изменения

- `MCComposerStyle` — общие цвета, кисти, кнопки и заголовки редактора.
- `SMCComposerWorkspaceShell` — переиспользуемая оболочка с отдельными слотами каталога, превью, схемы, инспектора, библиотеки и транспорта.
- VFX Composer использует новую оболочку и существующие action/session/provider widgets. Каталог расположен слева, инспектор справа, библиотека снизу.
- Полный вид показывает превью и схему рядом; компактный позволяет переключаться между ними. Есть автоматический выбор по доступному размеру окна.
- Библиотеку можно развернуть и скрыть. Режим плотности, вид библиотеки, её доля высоты и центральная вкладка сохраняются в локальной Editor-конфигурации проекта. Ручные ширины сохраняются при переключениях в открытом окне.
- Воспроизведение, пауза, остановка, сценарий, повтор и звук доступны в общей нижней строке при любом центральном виде.
- Галереи Niagara и звуков приспособлены к широкой нижней панели. В звуковой галерее список виртуализирован, параметры выбранного источника и кнопки находятся справа.

## Границы этапа

Это перенос основы интерфейса, а не завершённый SFX Composer. В отдельном SFX-окне пока нет публичного входа. До его подключения нужно выделить общий action document и владение preview: существующая `FMCVFXActionSession` создаётся на окно и зависит от активного preview-контекста. Простое копирование окна создало бы независимые черновики звука.

Событийное аудио продолжает использовать существующие `SFXSlots`, GUID слоёв и writer `ApplyAll`. Музыка/атмосфера используют существующую общую `FMCComposerSceneAudioSession`. Канонические данные, runtime-поведение, пакеты и настройки cook этим этапом не изменялись.

Галерея показывает уже импортированные Unreal-ассеты. Постоянный проводник внешних аудиопаков, waveform/длительность, плоские группы случайных вариантов, Ready/Lock и адресная замена выбранного слоя при примерке — последующие этапы. Существующая примерка добавляет временный источник к событию.

Новые brushes существуют только в editor Slate; новых runtime-ресурсов для manifest/prewarm нет.

## Проверка

- `MessControlEditor Win64 Development`: **PASS**, UE 5.8.1. Первая попытка выявила затенение поля локальной переменной; исправлено до успешной сборки.
- `git diff --check`: **PASS** для изменённых UI-файлов.
- Независимый review: исправлены пропадающий транспорт, сброс ручных ширин и незакрывающееся меню плотности.
- Сохранность исходников относительно копии до этапа: методы от деструктора до `Snapshot` и публичные методы после него сохранены; прежние незавершённые изменения scene audio не заменялись.
- Визуальная проверка реального окна: **PASS** для 1920×1080 и 1280×800. Авто-плотность переключилась; в компактном режиме доступны каталог, инспектор, библиотека и транспорт. Скрытие и возврат библиотеки проверены.
- Снимок action session до/после смены раскладки совпал полностью. После Play/Stop сохранены GUID черновика, revision, dirty-флаги, канонический владелец и данные событий.
- Реальный `Consumable_Rocket / Target` в отдельном transient world: **PASS**, получены `Start`, `LoopStart`, `Impact`, `End`, `ActionFinished`; после проверки `running=false`. Это sandbox preview, не PIE.
- Обнаружено 114 действий каталога, 179 Niagara-источников выбранного поиска и 77 звуковых источников. Числа не означают полную адаптацию/проверку всех действий.
- 7 направленных проверок снимков: **PASS** (`Results.json`). Новые native test suites не добавлялись.

Сохранены `NativeFullHD.png`, `NativeFullHD_SFX.png`, `NativeCompact.png`, `NativeCompact_Graph.png`, `NativeFinal.png`. Первичная Python-попытка Play использовала неэкспортируемый enum; скрипт исправлен на существующий строковый API `"Target"`, затем сценарий выполнен успешно. Ошибок/assert/crash от нового Slate UI не обнаружено. Звуковая слышимость отдельно не оценивалась: preview audio оставался выключен.

Существующие ограничения UI: пояснение непроверенного родного звука повторяется в SFX-инспекторе; строка статуса после остановки может сохранять предыдущее сообщение о проигрывании, хотя runner уже остановлен. Эти сообщения не менялись в этом этапе. После первого Play были ожидания компиляции Niagara/шейдеров в новом Editor-кэше; это не проверка packaged readiness/PSO.

Рабочие доказательства и скрипты: `E:/CodexWork/MessControl/Validation/ComposerShell_20261114/`. Кэш и временные файлы запуска направлены на E:. UBT пишет trace в свой фиксированный путь на C:; trace двух попыток перенесены в этот каталог на E: после завершения сборок.

Package/cook и сетевые проверки не запускались.
