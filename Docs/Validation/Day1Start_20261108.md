## Изменение

- После получения актуального `IcePresentationScope::Required` загрузчик
  повторно раскрывает зависимости общей библиотеки. Ранее библиотека могла
  считаться уже обработанной при ещё неизвестном scope и теряла Freeze-профиль
  из списка запросов. Новые пути проходят обычные async-волны и удержание
  ресурсов до подготовки персонажей. Unknown/чужая эпоха ждут сервер;
  NotRequired не подгружает Freeze. Та же проверка действует в asset-only пути.
- После вопроса об универсальности добавлен общий барьер перед раскрытием
  любой завершённой async-волны арены: пока серверный scope неизвестен или
  принадлежит старой эпохе, корень не помечается обработанным и его зависимости
  не фиксируются. Файлы корней могут загружаться параллельно с репликацией.
  Это общий порядок для зарегистрированного графа ресурсов; отдельная проверка
  покрытия всё ещё нужна для не объявленных в профилях/манифесте ресурсов.
- Удалён ручной `ReleasePSOPrecacheData` для заимствованных ID из
  `PrecacheMaterialPSOs`. Их уже освобождает владеющий `FMaterial`; прежний
  повторный вызов при GC совпадает с обоими assert-стеками
  `PSOPrecacheMaterial.cpp:440`. PSO остаётся включённым.
- Контакт бензопилы передаёт настоящую точку и плоскость разреза в общий
  обработчик еды. В новом режиме крупные остатки снова режутся, мелкие
  завершаются через существующий `Food.AutoMouth`. Предел 220 см, бюджет зачёта,
  прежняя частота контактов и движение/остановка пилы сохранены. Твёрдая целая
  еда сначала вскрывается двумя прежними контактами; готовность по размеру
  больше не позволяет съесть целую оболочку. Старый ручной режим сохранён.

Большой RTT увеличивает окно до прихода серверного scope и мог проявлять
гонку. Исправление добавляет ожидание существующих данных и локальную
асинхронную загрузку; новых RPC и постоянной сетевой нагрузки нет.
