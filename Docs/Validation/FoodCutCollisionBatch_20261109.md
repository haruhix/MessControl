# Пакетная подготовка коллизий нарезанной еды — 2026-11-09

Продолжение [однократной подготовки геометрии](FoodCutPrepared_20261109.md).
Исходный проверенный case: одна сохранённая гроздь `Bacon` / `SM_GrapesPurple`,
scale 40, настоящий нож, 47 частей / 9 готовых / 38 физических.
После предыдущего исправления пик GameThread равен 89,0343 мс,
FrameTime — 94,0344 мс. Именованный CPU scope спавна частей занимал
51,269 мс inclusive, включая 28,069 мс установки коллизий.

Этот проход переносит чистый расчёт выпуклых форм в пакет независимых задач.
Акторы, UObject, BodySetup и подключение физики остаются на игровом потоке.
Готовые receipts не нуждаются в физической форме. Конечная установка должна
использовать готовые вершины и индексы без повторного hull build.

## Реализация

`PrepareConvexBatch` копирует только нужные вершины физических частей и
обрабатывает независимые запросы через `ParallelFor`. Workers создают отдельные
результаты и не обращаются к UObject, weak-кэшам, `TSharedPtr` или общим
счётчикам. Все задачи завершаются до спавна; при отказе хотя бы одной формы
частичные результаты не публикуются. Готовая неизменяемая форма хранится рядом
со снимком геометрии, с учётом политики planar proxy.

Индексы строятся по уже рассчитанным граням convex. Установка на игровом
потоке заполняет vertex/index data и использует
`FKConvexElem::EConvexDataUpdateMethod::UpdateConvexDataOnlyIfMissing`.
Стандартная принудительная перестройка через `BuildIndices` больше не нужна.

`CustomPreSpawnInitialization` отключает начальную коллизию и очищает
дефолтный StaticMesh до регистрации компонентов нового куска. Штатные
`OnRep_Item`/`BuildCutVisual`/`OnRep_Phase` устанавливают и включают конечную
форму. Масштаб, объёмный предел 110³, физические свойства и видимая геометрия
сохраняют существующие правила. Новых runtime-ресурсов нет.

проверки прошли; новый collision oracle ошибочно пропускал pivot исходного
меша. Исправлен только эталон теста, затем Editor пересобран и этот тест
прошёл в `Native02`. Проверены proxy-вершины/границы, готовность каждого
кусочка по 110³, отсутствие convex у receipts, одна общая пачка для 38
физических частей, cache/reconstruction/повторный RepNotify, обычные и
повторные срезы в обоих режимах, атомарный отказ и разрешённый planar proxy.
