# Gameplay fixes — 2026-11-14

## Changes

- Fish: the visible wallet counter waits for the reward token's counter arrival
  and refreshes with its pulse. Authority still accepts and saves the catch.
  Pending receipts, queue overflow, cancellation, missing targets and observed
  grill debits/refunds are handled without granting currency from UI code.
- Task coins: the existing ten-coin objective reward now also runs for completed
  food portions and coffee cleanup, alongside the existing booster chest.
  Completion IDs retain once-per-run settlement through placement/choice retries.
- Victory bonus: +10% of this round's actually credited task coins per surviving
  arena tooth, rounded down once, subject to the personal wallet cap. Damaged
  surviving teeth count; lost/consumed teeth and old Hub savings do not. The bonus
  settles once, is saved in the ordinary Hub wallet and appears in result text.
  Run receipts reset on restart and survive PlayerState replacement.
- Hub basketball: LMB picks up; a fresh LMB press throws. Holding the pickup
  gesture cannot immediately throw. Optional RMB aim, E drop and gamepad controls
  remain. Hints and localized copy use the new mouse controls; LMB keycap text is
  prepared through the existing loading barrier.
- Grapes: the saved breakfast menu's legacy `Bacon` row uses SelectionWeight=0.
  The row, green/purple grape meshes and all other fields remain. Tutorial food
  selection respects the same listing weight and substitutes an eligible food.
  The canonical day-one authoring default also keeps this row disabled.

Existing `Reward.TaskCoins` Composer registration, runtime presentation and
resource preparation are reused. No new material, texture, mesh, animation,
Niagara System or widget brush is introduced by this change.
