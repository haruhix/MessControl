Причина была в Niagara rename-транзакциях временной сборки: штатный `RenameParameter` открывал `FScopedTransaction`, и Ctrl+Z попадал в неё вместо пользовательского Add. Проверенный повтор **двухслойный Play → Undo до одного слоя → новый singleton Play при доступном Redo → Redo** вернул два слоя и прежний GUID Flash. Ниже перечислены только корректные `Proper*14` отчёты; ранние попытки `Added14`/`CorrectAdded14` имели неверную автоматизацию setup и не считаются успешными.

Source-починка оборачивает только временную generated-сборку собственной scoped-транзакцией с Cancel при выходе, включая ранние отказы. Перед ней запрещён активный пользовательский transaction/Undo/Redo. Это существенно: UE 5.8 не поддерживает partial nested Cancel и иначе отменил бы чужую транзакцию целиком. Независимый source-review подтвердил, что `UTransBuffer::Cancel` восстанавливает прежние `RemovedTransactions` и `PreviousUndoCount`, включая Redo; глобального Reset нет. Положительный runtime-повтор Build14 подтвердил Undo/Redo именно этого воспроизведённого сценария; полная матрица транзакций остаётся отдельно.

Следующее пользовательское уточнение — двойной клик слоя для открытия настоящей исходной Niagara System. В source handler использует только выбор слоя, загрузку persistent NS и `UAssetEditorSubsystem::OpenEditorForAsset`; собственных Modify/Save/Assign вызовов нет. Это проверка намерения кода, а не гарантия отсутствия любых editor fixups: actual открытие и финальное медиа Build15 ещё ожидаются. Новая версия ReviewBoard пока не публикуется.

`LifecycleRISignatures10.json` и native T3D readback выявили конкретное различие: SystemUpdate store Flash сохранил orphan `Constants.PhysicalSmoke.*` после удаления smoke-emitter. Старый comparator исключал только aliases текущих emitter handles; поэтому этот бывший emitter-cache ошибочно считался SystemState-настройками. У Smoke текущий PhysicalSmoke исключался, и одинаковые системные lifecycle настройки получали разные подписи. Это установленная причина ложного отказа сохранённой пары.

Узкая source-починка сравнивает RI только namespace реальных system-module aliases, определённых предварительно проверенной topology. Независимое чтение `MCVFXComposerBuilderLibrary.cpp:103–127` не выявило нового fail-open: требование empty SystemSpawn / единственный standard SystemState, сравнение версии/inputs/static/linked values и warmup/tick/determinism/EffectType сохранены. Неизвестный custom system module отклоняется до RI-фильтра. Source review дополнен положительным повтором пары в свежем Editor11; намеренно отличающийся настоящий SystemState этим повтором не проверен. Сравнение реального lifecycle не отключено.

## Сохранённый неуспех и исправление

В Editor07 воспроизведён настоящий crash при сборке Smoke с private User-параметрами: `RenameUserParameterForSystem` создавал внутренний data-only `FNiagaraSystemViewModel` без `MessageLogGuid`; stack subscription достигала проверки непустого ключа в `NiagaraMessageManager.cpp:291`. `Editor07.log` и `Crash07/` остаются диагностикой неуспеха.

Исправление создаёт scoped data-only view model **только для owned transient copy**, задаёт новый message GUID и сохраняет штатный экспортированный rename helper. Graph references, exposed defaults и renderer bindings продолжают переименовываться штатным API. VM живёт на протяжении обработки source copy и уничтожается раньше неё; исходные donor assets не регистрируются для изменения. Build08 и последующее создание четырёх templates / native Smoke / двух private namespaces подтверждают устранение именно воспроизведённой ошибки. Старый crash не переименован в успешный тест.

## Что ещё не подтверждено этим проходом

- Финальная пригодность актуальной медиаверсии для ревью. В историческом Editor15 родной журнал подтвердил открытие RocketStart/Smoke/Impact по double-click; неподдержанный Python `editedAssets` probe не считается проверкой. Это не заменяет текущий общий runtime-проход.
- Художественная оценка всех четырёх starter-форм в штатной игровой камере. Принятая компоновка Build13 и native DnD/Play не заменяют эту приёмку.
- Отмена DnD по Esc ещё не проверена. Упоминание Esc в runtime-подсказке не считается результатом теста.
- Полная матрица Undo/Redo, empty/disabled-stage roundtrip, stale-source/profile guards, намеренный save failure/rollback и долгий repeat/leak test. Source review защит не является выполнением этих сценариев.
- Художественная эквивалентность любых произвольных исходных/generated NS, весь каталог, все остальные contextual adapters.
- Первый холодный packaged запуск, GPU/overdraw, сетевой режим, микрофон, cook/package. Новые runtime-ресурсы должны сохранять manifest reachability; локальный тёплый Editor-cache не доказывает холодную readiness.
