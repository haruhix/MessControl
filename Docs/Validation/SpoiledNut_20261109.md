# Испорченная нарезка и масштаб ореха — 2026-11-09

## Изменение

- Свежая и испорченная обычная еда используют один предел собственного объёма: 110³ = 1 331 000 см³. Каждый готовый связный кусок завершается отдельно, крупный сосед остаётся.
- Испорченный кусок направляется через сохранённую переднюю кромку выхода для мусора, с учётом направления маркера. Отключённая ручная зона не отключает этот маршрут. Отсутствующий выход отклоняет всю операцию без потери исходного продукта.
- Выброс имеет отдельный одноразовый флаг и событие `Food.AutoMouth/Discard`. Он не вызывает награду свежей еды и не увеличивает `FoodSwallowed`/`MealSequence`. Обучение принимает явное подтверждение автоматического выброса.
- В `DT_NutRainMenu` скорлупа и мякоть используют масштаб исходного ореха. При высоте целого 180 см высота скорлупы теперь около 179,9 см вместо 70 см, мякоти — 152,8 см вместо 59,5 см. Размер врагов 116 см сохранён. Runtime-настройка и рецепт авторинга согласованы; отдельные запечённые коллизии подготовлены под новый масштаб.
- Ореховые боеприпасы события сохраняют владение событием и существующие E/Q. Новые меши, анимации и художественный Niagara не создавались.

### Устройство визуального черновика

1. Контракт: декоративный разлом готовой порции после реального принятого контакта ножа. Решения о нарезке, цели и зачёте остаются в механике.
2. `NS_Food_Juicy_Draft_20261109`: два редактируемых world-space CPU mesh emitter; 7 крупных кусочков + 22 мелкие крошки. Оба используют существующий 12-треугольный меш, отдельный draft-материал с roughness 0,32/specular 0,45. Общие исходники не меняются.
3. Порядок: единственный burst → штатная инициализация/ParticleState → явные Position/Color/Scale/Orientation. Начальные 0,13–0,175 с дают разлёт, затем разные части собираются по ограниченной кривой к цели и уменьшаются в конце жизни. Самостоятельное завершение без цикла.
4. Сохраняются типизированные `User.Color`, `TargetOffset`, `Duration`, `Radius`, `Intensity`, `Seed`. Они получены из принятого события; презентация не повторяет игровой RNG. Обновление выполняется внутри Niagara, без покадровой сетевой отправки частиц.
5. Нет столкновений, Chaos, дочерних физических акторов, data interfaces и авторитетных particle events. Пространство — world, конечная точка фиксируется механикой.
6. Dynamic CPU bounds следуют полному пути. Сохранён прежний one-shot Effect Type Deactivate/Kill; MaxPoolSize=16, Prime=2. Это настройки повторного использования, не предел одновременных систем. Глобальные настройки Effect Type не менялись.
7. Лимит одного обычного burst — 29 частиц / 348 треугольников. В записанном настоящем разрезе приняты обе половины, поэтому наблюдаемый пик двух draft-cue — 58 частиц / 696 треугольников. Это счёт геометрии, не измерение GPU-time. Обычная игровая нагрузка, overdraw и несколько игроков для unapplied-черновика не профилировались.
