# Один день: первый авторенный фрагмент

Обычный `BP_MouthGameMode` запускает короткое обучение и последовательность:

1. Чистка зуба, разбивание еды ударами до полного разрушения, чистка языка. Сбор и доставка не входят в короткое обучение.
2. Общая зубочистка в центре языка: волна боли при попадании, удержание E для извлечения, удар киркой, лечение язвы удержанием ЛКМ со спреем. Пульсирующая подсказка меняется вместе с действием.
3. За обучение команда получает первый уровень. Каждый выбирает один личный перк из трёх. Персонажи и выборы сохраняются при переходе.
4. Пять секунд передышки после первого выбора, затем обычный приём пищи: три продукта с интервалом 1,5 секунды. Каждый продукт сопровождается грязью. Переход ждёт разбивания всей еды и уборки; после этого ещё четыре секунды передышки. Новые личные выборы также завершаются до орехов.
5. Ключевое ореховое событие: серии падающих орехов, затем два ореховых босса с врагами. Обычные события директора в этот момент не запускаются. Событие завершается только после победы над обоими боссами и оставшимися врагами.
6. После победы адаптивный директор поддерживает арену: в основном еда, кофе, кофейный потоп и перец, а также чистка и ремонт. Перец нужно выбрасывать через выход, а не разбивать. Авторенный фрагмент отмечается завершённым в F3; игра продолжается без автоматического финального босса.

Предыдущий батч изменений начала, зон падения, вращения танка и учёта стаков включён в сборку
Editor по запросу пользователя. Материал `/Game/Gameplay/CoreLoop/M_NutLandingShadow`
мигрирован в кольцо с отсчётом, а настройки кофе сохранены в `DA_SingleDayDirector`.
Игровые и сетевые проверки этих изменений отложены до общего батча;
результаты прогонов ниже относятся к предыдущей версии.

Текущий батч усиления добавляет обычные удары мечом между способностями, явные
cooldown, уход мага из фокуса телепортом, волну боли при столкновении Roll с зубом
и сильное отталкивание танком. Попадания показывают фактическую потерю HP после
щита и ограничение оставшимся здоровьем; удары по игроку дают вспышку и короткий
отклик камеры. Разрушение еды сопровождается частицами без игровых фрагментов.
Размеры и частота подачи сохранены в двух профилях через отдельный Unreal Python
авторинг `Tools/Unreal/retune_encounter_pressure.py`. Весь батч включён в успешную
сборку `MessControlEditor Win64 Development` 9 октября 2026 года по запросу
пользователя. Игровые и сетевые проверки отложены до общего батча.
Редактор открыт на `L_Mouth`; live MCP подтвердил новые размеры, teleport/push
настройки, частоту еды и сложность `9`. Play не запускался.

Ориентир полного будущего забега — **25–35 минут**. Сейчас авторен только первый
фрагмент с целью **3–4 минуты** для человека; это цель для игрового тестирования, а не подтверждённая
длительность. Следующие ключевые события ещё не созданы. Отдельного таймера победы
нет: завершение текущего фрагмента не означает победу в полном забеге.

Обычная еда разрушается ударами: при исчерпании HP целый продукт исчезает без россыпи фрагментов и сразу даёт общий XP и зачёт задачи. Чистка, ремонт, лечение и разбивание льда также дают общий XP. В обучении отдельные действия не начисляют XP; первый уровень выдаётся за завершение урока. Каждый уровень создаёт независимую очередь личных предложений. Очередь и перки переживают замену персонажа; повторная отправка выбора не выдаёт награду второй раз. Легендарный инструмент из личного предложения принадлежит выбравшему игроку. Исходные сундуки сохраняют свою отдельную механику.

Поглощение, сбор в стопку и доставка в глотку сохранены для будущих механик и legacy-уроков. Они не обязательны для обычной еды в текущем coreloop. Короткий урок засчитывает разбивание через `FoodCut` после завершения удара; исчезновение цели или доставка сами по себе не переводят его дальше.

## Настройки для тестирования

- `/Game/Gameplay/CoreLoop/DA_NutRain`: профиль ореховых серий, врагов и двух боссов. Решения размера серии получают состояние команды через SingleDayDirector: обычно 2 ореха для ослабленной команды, 3 для средней, 4 для здоровой, с небольшой вариацией seed. Переход из дождя запрещён раньше четырёх завершённых серий и 40 секунд; здоровая команда может получить ещё одну серию или до восьми дополнительных секунд.
- `/Game/Gameplay/CoreLoop/DA_SingleDay`: массив `KeyEvents`; сейчас один слот `NutEncounter`, его варианты и 25 XP за завершение. `DirectorSupportSeconds` задаёт поддержку между соседними уже авторенными слотами; после последнего слота поддержка не имеет дедлайна. `RunTargetMinMinutes=25` / `RunTargetMaxMinutes=35` — ориентир полного забега. `bLegacyTimedFinale=false`; старые `DirectorSeconds=30` и `FinalBossClass` используются только при явном включении legacy-прототипа.
- `/Game/Gameplay/CoreLoop/DA_SingleDayDirector`: профиль поддержки с фиксированной runtime-сложностью `9`: сохранённые `MinimumDifficulty=MaximumDifficulty=1`, `DifficultyMultiplier=9`. Первичная оценка через `1.5` секунды, решения каждые `1.25` секунды с вариацией `.8–1.3`, адаптация `16` секунд. Старый `/Game/Data/DA_GameDirector` сохраняется для legacy-дней.
- `AMCGameState.Progression`: первый порог 50 XP, прирост порога 25. Личные карточки используют реальные инструменты и три повторяемых восстановительных перка; пустые старые заглушки отключены для повышения уровня.

После масштабирования профиль поддержки даёт `TargetPressureMin=1.62`,
`TargetPressureMax=4.95`, `PressureLimit=8.55`, `FoodWorkPerPlayer=288`,
максимум 12 целых предметов еды; лимит 80 фрагментов сохранён для будущих механик.
Обычная еда фрагментов не создаёт. При фиксированной сложности
целевая нагрузка адаптируется в пределах `1.62–4.95` по производительности,
стрессу и здоровью команды; начальная цель равна `3.285`. Сложность остаётся `9`.
Текущий расчёт обычной еды учитывает оставшиеся HP, реальные нож/кирку, личные
улучшения инструментов и подход к видимой поверхности продукта. Будущие фрагменты,
сбор в стопку и доставка не прибавляют нагрузку. Состояние стаков сохранено
как диагностические данные; перенос перца и других опасных предметов учитывается отдельно.
Каждая обычная подача еды создаёт одно пятно языка той же партии; отказ от подачи
удаляет её пятно. В рабочей копии профиля положительные веса этих событий имеют
минимумы: еда `12`, кофе `4.5`, кофейный потоп `2`, перец `2`.
Явно отключённые события с весом `0` остаются отключёнными. Остальные обычные
события выбираются с множителем веса `.35`. Cooldown еды `3` секунды,
интервал порций `2.25` секунды, до четырёх продуктов в порции; каждый следующий
продукт проходит отдельную проверку нагрузки. Передышка после разгрузки до `1.5`
секунды, а вес случайного ожидания при наличии работы уменьшен с `1` до `.35`.
Cooldown кофе `10` секунд,
потопа `75`, перца `60`; обычная порция кофе создаёт до двух пятен.
Общий интервал событий — `6` секунд. На пустой арене директор не выбирает
случайное ожидание или пустую передышку; cooldown и доступность игроков сохраняются.
При наличии работы новые обычные события могут перекрываться по запасу нагрузки.
В журнале поддержки видны оставшиеся продукты, уборка и время работы с едой.
Эти настройки действуют только
между ключевыми событиями: еда, кофе, кола, чистка и другие обычные задачи.
Ореховое ключевое событие использует свой профиль и не изменено этой настройкой.

В режиме поддержки выключены дневные гейты. В конечном интервале сохраняется
оценка «успеет ли событие до следующего ключевого этапа»: для еды берётся полное
время подхода, разрушения, пятна и полёта без деления на размер команды;
перед спавном прогноз проверяется повторно. В бессрочной поддержке дедлайна нет.
Обычные события допускаются по нагрузке, здоровью, выносливости, наличию
игроков и cooldown; срочная угроза, движение языка или глотание приостанавливают
новые помехи. Случайные сундуки и боссы отключены. Директор сохраняет фазы
нарастания, разгрузки и передышки, но после конца фрагмента не запускает финальную
уборку, следующий день или победу по времени.

Для расширения последовательности добавляется следующий авторенный слот в
`KeyEvents`, а не выдуманный запасной эвент. Сейчас поддержан только тип
`NutEncounter`; новые типы требуют реализации и отдельного авторинга.

Между двумя сохранёнными слотами `DirectorSupportSeconds` создаёт конечное
окно поддержки: положительный `DayEndsAt` останавливает директор и передаёт
управление следующему ключевому событию. После последнего слота `DayEndsAt=0`;
проверка окончания применяется только при `DayEndsAt>0`, поэтому прежние 30
секунд, длительность legacy-дня и ориентир 35 минут не завершают этот режим.

Модель танка — производный `/Game/Gameplay/CoreLoop/NutTank/SK_NutTank`,
экспортированный из `Nut_Tank.blend` вместе со щитом и дубинкой. Исходный
`/Game/FromBlender8/SM_Nut_Tank` и его материалы сохраняются. Семь клипов в
подпапке `Animations` используют общий производный скелет: `Idle`, `Walk`,
`WalkLeft`, `WalkRight`, `Melee`, `Jump`, `Transform`. `Jump_TranseBall`
соответствует последнему: во время подготовки полный воин со щитом и дубинкой
переходит в отдельный меш шара, во время переката виден только вращающийся шар,
восстановление возвращает модель воина. При смерти в форме шара эта форма
сохраняется до завершения реакции смерти.
Положения контакта в клипах задаются
`TankMeleeImpactFraction=.5`, `TankJumpTakeoffFraction=.25` и
`TankJumpImpactFraction=.7`; это начальные настройки, требующие игрового просмотра.
Экспорт: `Tools/Blender/export_nut_tank.py`; импорт через консоль Unreal/MCP:
`py "E:/DEVGAME/MessControl/Tools/Unreal/import_nut_tank.py"`.
Первичный импорт танка выполнен через MCP в Editor: десять пакетов сохранены, длительности всех
семи клипов совпали с экспортом, оригинальные пакеты модели и материалов
сохранили хеши. Отчёт — `Saved/Checks/NutTankImport.json`. Предыдущая сборка с
этими анимационными полями завершилась успешно; она ещё не включала описанное
ниже общее обновление поз и эффектов.

Из `Nut_Wizard.blend` подготовлен полный маг со своим совместимым ригом для
`/Game/Gameplay/CoreLoop/NutWizard/SK_NutWizard`. Восемь клипов в подпапке
`Animations`: `Idle`, `Walk`, `Cast`, `HeavyCast`, `Summon`, `Rain`, `Hit`, `Death`.
`Cast`, `Summon` и `Rain` сохраняют три авторских действия; `HeavyCast` использует
действие дождя как запасной тяжёлый каст. Циклы ожидания и ходьбы, реакция на удар
и падение созданы на исходном риге как процедурные опорные клипы. Исходные
`.blend` не сохраняются; упакованные текстуры отдельно записаны вместе с
FBX и манифестом в `ArtSource/NutWizard`. Экспорт:
`Tools/Blender/export_nut_wizard.py`; импорт после общей сборки:
`py "E:/DEVGAME/MessControl/Tools/Unreal/import_nut_wizard.py"`.

Обоими скелетами управляет нативный `UMCNutBossAnimInstance` с pose proxy.
Игровой поток готовит снимок фазы, скорости, направления цели и весов клипов;
вычисление позы использует этот снимок и смешивает клипы с предыдущей позой.
Фаза подготовки, контакт, полёт и восстановление задают нормализованную позицию
в клипе, поэтому число кадров и длина FBX не определяют длительность атаки.
Перемещение, попадания и толчки остаются серверными; root motion выключен.
Процедурные слои добавляют дыхание, наклон при движении, прицеливание корпусом,
головой и руками, защитную позу щита и реакции на попадания. IK правой руки мага
доводит ладонь к точке выпуска без растягивания руки. Серверная точка выпуска
задаётся `MageCastOffset` и не зависит от вычисленных косметических костей;
`cast_palm` — необязательный визуальный socket на `hand_r`.

Дождь мага поддерживает среднюю позу каста и процедурное движение рук всё время
серверного канала; короткий клип не заканчивает позу раньше заклинания.
После канала отдельная фаза восстановления возвращает мага к движению.
Реакции на удар и щит накладываются на текущую позу. Смерть мага использует
`Death`, смерть танка — процедурное падение; визуальное завершение длится
`DeathSeconds=2.4`, при этом урон и новые атаки прекращаются сразу.

В текущем исходном коде эффекты разделены по этапам: `CastCharge` накапливает
огонь у точки выпуска, `CastRelease` даёт вспышку при запуске огненного ореха,
`RitualCast` поддерживает магический ритуал призыва и дождя. Для танка есть
`Transform` при переходе в шар, `RollTell` с предупреждением и следом движения,
коридор рывка, круг прыжка и кольцо удара при приземлении. `ShieldHit` и
`DeathBurst` показывают блок щитом и смерть. Дождь заклинания сохраняет область
и штормовой эффект на протяжении канала, отдельные орехи получают свои
предупреждения и удары. Эти эффекты косметические; урон выполняют серверные
боссы, снаряд и отдельная механика падающих event-орехов.

акторы удалены, грязных пакетов после очистки нет. Этот статический просмотр
не подтверждает проигрывание боевых фаз или сетевую синхронизацию.
Игровой и сетевой прогон обновлённых поз и эффектов отложен до общего батча;
прежние VFX-кадры и сетевые проверки не подтверждают это обновление.

Зубочистка падает в язык за 0,9 секунды и только при контакте создаёт язву и
одну большую волну боли. Её язва не запускает автоматические микроволны и не
реагирует на еду. Новое наступание живого игрока может вызвать боль; стояние на
язве не повторяет волну. Панель инструментов доступна во время обучения.
Вытягивание зубочистки через E работает и рядом с сундуком; спасение товарища
из мимика сохраняет приоритет.

Ореховый дождь использует неровные серии падений, паузы, группы близких целей
и разные направления парабол. Перед попаданием на языке появляется контур зоны
радиусом 180 см с заполнением до приземления. Поддерживающий контакт с языком
однократно наносит 18 урона игрокам в зоне и отталкивает их; удар имеет отдельную
вспышку, кольцо и частицы. Обычная подача еды сохраняет прежний лёгкий толчок.
Предупреждения исчезают при приземлении и очищаются при остановке эвента.
Танк вращается с предупреждением, медленно поворачивает и отскакивает от границ;
попадание наносит урон и отталкивает. Во время вращения щит не блокирует урон.
Боты реагируют на предупреждения обычным движением и
атакуют ожившие орехи киркой.

Общий реплицируемый `AMCGameState.DirectorDecisionLog` хранит до 128 последних
записей обучения, ключевых событий и обычного директора. Обновление карточки
текущего события не стирает историю. В F3 есть отдельная прокручиваемая колонка
журнала и локальный переключатель подробных наблюдений на HUD. Постоянная плашка
`F3 · Журнал директора` после завершения фрагмента показывает `Фрагмент готов`.
История очищается только при новом забеге.

`MC.Bots` и запуск из F3 пропускают обучение только для диагностической команды.
Первый уровень выдаётся после появления всех участников; боты выбирают личные
перки сами, человек в `coop` выбирает свою карточку. `MC.Bots.Stop` возвращает
обычное обучение. Подробности и отчёты: `Docs/PlaytestBots.md`.
Для обычной еды цель бота — разбить продукт ударами; перенос и доставка сохраняются
для будущих задач, а не как обязательное продолжение разбивания.

## Ледяное событие — правила 10 октября 2026

Карта изменения механики, настроек, F3 и будущего polish с постоянными
якорями: [IceEvent.md](IceEvent.md). Перед правками холода использовать её.

После орехового события и его интервала запускается `AMCIceEvent`; тот же
сценарий доступен в F3 как «Зима близко». Цель — разбить центральный ледяной
кристалл киркой. Используются обновлённые материалы языка и персонажа из
коммита `9189819`, а сосульки, центральный кристалл и лёд на ногах используют
`/Game/Art/Materials/ice/MI_Ice`.

Тёплые зоны выбираются у дальнего допустимого края языка; следующая находится
далеко от предыдущей. Если поверхность позволяет, между центрами сохраняется
не менее двух начальных радиусов, даже на несимметричном языке. Радиус
постепенно уменьшается с 330 до 200 см за её
собственное время жизни, в том числе во время перекрытия. Время жизни зоны с
момента её появления: 45, 40, 35, 30, 25, затем всегда 20 секунд. Следующая
зона начинает согревать за 10 секунд до исчезновения предыдущей; перекрытие
входит в её собственное время жизни. По таймеру на одной из действующих зон
появляется кристалл: пока он цел, эта зона не отогревает игроков и снова
покрывается инеем. Кирка восстанавливает согревание, таймер зоны продолжает идти.

Сосульки выбирают случайного живого игрока на всю серию из трёх ударов. Каждая
новая отметка фиксирует текущую позицию выбранного игрока и после появления
не следует за ним. Между началами серий 12 секунд. Настройки прототипа:
предупреждение 2,2 секунды, шаг серии 1,2 секунды, урон одного попадания 35.

Центральный кристалл предупреждает о конусе холодной бури, фиксирует направление
и затем замораживает ноги попавших в конус. Это отдельное состояние от общей
шкалы холода: руки и инструменты доступны; киркой можно освободить себя или
стоящего рядом союзника. Настройки прототипа: первое предупреждение через
18 секунд активной фазы, подготовка 2,5 секунды, затем 18 секунд до следующего
предупреждения после удара; дальность 2600 см, полный угол конуса 70°, здоровье
льда на ногах и кристалла зоны 80. Кристаллы зон проверяются каждые 16 секунд.

Общий холод по-прежнему накапливается вне работающей зоны и смертелен при
заполнении шкалы; согревание постепенно снижает шкалу. Оно не заменяет кирку
для освобождения ног. Завершение, замена события и F3-остановка убирают
препятствия, предупреждения, покрытие, скользкий пол и заморозку ног.

Для этого варианта используется `Tools/TestIceColdRework.ps1`: `-Mode Network`
проверяет двух настоящих peers на сохранённой `L_Mouth`, `-Mode Visual -Players 1`
снимает кадры с игровыми временными метками. Контакты кирки проходят через
Enhanced Input и обычный серверный код инструмента. Сценарий расставляет игроков
для проверок, не меняя здоровье кристаллов и производственные таймеры.
`Tools/BuildEventCaptureVideo.py <Frames> <output.mp4>` собирает кадры с их
исходными интервалами; большие промежутки без съёмки вырезаются и перечисляются
в JSON рядом с видео.

Визуал холода хранится отдельно в `/Game/Gameplay/Cold/VFX`: пять lightweight
Niagara-систем, шесть материалов и гранёный `SM_IceShard`. `AMCIceEventVFX`
работает локально по реплицированному состоянию события: подготовка сосулек,
осколки и пыль от попаданий, конус прозрачного ветра со снегом, реакции
кристаллов и замороженных ног. Сосулька появляется только на последних
0,55 секунды падения; отметка заранее остаётся на земле. Материалы льда
коллеги не изменяются. Дополнительные FAB-ассеты для этого варианта не нужны.

На событие выделено десять повторно используемых Niagara-компонентов и
не более восьми одновременно удерживаемых кратких выбросов. После успешного
разрушения ядра остаётся эффект на 1,65 секунды; надёжный сетевой сигнал
сохраняет его при немедленном удалении события директором. Отмена через F3
сразу убирает все эффекты. Выделенный сервер их не создаёт.

`Tools/Unreal/author_ice_vfx.py` создаёт и сохраняет только принадлежащие этому
проходу пакеты; уже существующие материалы и системы сохраняются при повторном
запуске. `Tools/TestIceColdRework.ps1 -Mode Visual -Players 2 -RequireVFX`
дополнительно проверяет загрузку ассетов, лимит выбросов, клиентский сигнал
разрушения, немедленное удаление события и очистку после отмены.
