# Перки забега

Таблица `/Game/Gameplay/Roguelike/DT_Perks` использует структуру `FMCPerkDefinition`. Сейчас в ней 12 пустых плейсхолдеров: шесть положительных и шесть отрицательных. Подбор фиксирует выбранный ID и количество стаков, но не меняет характеристики игрока и не создаёт предметы. Отображаемые названия временные; существующие технические ID сохранены.

Сундук выбирает три разные доступные строки одной полярности с учётом `Weight` и лимита `MaxStacks`. Игрок выбирает один вариант, после чего остальные исчезают. Для каждой используемой полярности должно оставаться хотя бы три доступных строки.

## Строка таблицы

- Имя строки — постоянный ID перка.
- `DisplayName`, `Description` и `Icon` — данные для представления награды.
- `Polarity`, `Weight` и `MaxStacks` — правила выдачи. Вес 0 исключает строку из случайного выбора; максимальный стак дополнительно ограничен 100.
- `EffectClass` — класс уникального эффекта. Пустое поле использует базовый `MCPerkEffect`, который ничего не делает.

В строке нет полей характеристик или процентных модификаторов. Будущие перки могут выдавать отдельные предметы, добавлять попытки возрождения или менять игровые правила через собственные эффекты.

## Подключение уникального эффекта

1. Создать Blueprint или C++ подкласс `MCPerkEffect`.
2. Назначить его в `EffectClass` нужной строки и заполнить описание и иконку.
3. Реализовать необходимые серверные события: `OnApplied`, `OnStacksChanged`, `OnRemoved`.
4. Сохранить таблицу и перезапустить Play: определения загружаются один раз при старте компонента.

Один серверный экземпляр эффекта принадлежит `MCPerkComponent` для каждого активного ID. Через `OwnerComponent → GetOwner` доступен `PlayerState`. `OnApplied` вызывается при первом получении, `OnStacksChanged` — при изменении количества стаков. В `OnRemoved` нужно снимать подписки, очищать таймеры и временные объекты; событие вызывается также при завершении компонента.

Эффекты, привязанные к телу игрока, подписываются на смену pawn у `PlayerState`: обычная смерть не вызывает `OnApplied` повторно. `GetWorld()` доступен для таймеров. Состояние уникального предмета или эффекта реплицируется через его игровой actor/component; экземпляры стратегии сами не реплицируются. UI получает `OnPerksChanged` и читает `ActivePerks`/`GetPerkDefinition`.

## Выдача и срок жизни

`UMCPerkComponent` — стандартный компонент `AMCPlayerState`. Сервер выдаёт перк через `ServerGrantPerk(ID)` после проверки сундуком права на награду. Это локальная серверная функция, а не клиентский RPC. `ServerGrantPerks(IDs)` сначала проверяет весь набор и выдаёт его целиком.

Реплицируются ID и количество стаков. Обычная смерть и замена pawn сохраняют перки; `CopyProperties` переносит их при замене `PlayerState`. Новый забег вызывает `ResetMatchScore → ResetPerks`. `RemovePerk(ID)` удаляет все стаки указанного перка. Удаление, сброс и выдача доступны только на сервере.
