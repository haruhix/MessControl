# Индексы кода и ассетов

В Codex подключены два локальных MCP: `codebase_memory` (codebase-memory-mcp 0.11.0) и `messcontrol_assets` (сервер этого проекта). Работающий редактор доступен через существующий `unreal_epic`. Экспорт ассетов выполняет редакторский плагин `MessControlProjectIndex`; UAssetAPI не требуется.

Экспорт запускает `UnrealEditor-Cmd` без UI, с `NullRHI` и `-DisablePython`: чтение выполняет C++, поэтому встроенный Python и его startup scripts не запускаются. Настройки обычного редактора не меняются.

## Установка на другом компьютере

Нужны UE 5.8.1, собранный редакторский target, Python 3.11+ и Codex CLI. В PowerShell из корня проекта:

```powershell
.\Tools\ProjectIndex\Setup.ps1
.\Tools\Build.ps1
python Tools/ProjectIndex/index.py refresh
```

Setup использует фиксированный Windows x64 релиз codebase-memory 0.11.0, проверяет SHA-256 и добавляет только два MCP в пользовательский config.toml. Предыдущая конфигурация копируется в `.codex/backups/messcontrol-project-index`. Глобальный установщик, сторонние инструкции и lifecycle hooks не запускаются. Для своего пути к Python или бинарнику используй `-PythonPath` / `-CodebasePath`. После настройки перезапусти Codex или открой новый чат проекта, чтобы клиент загрузил инструменты.

## Обновление

Индекс кода следит за сохранёнными правками Git-проекта, включая незакоммиченные. `.cbmignore` исключает контент, артефакты, промежуточные данные и бинарники. Код плагина, инструменты, конфигурация, документация и тесты входят в индекс.

В этом checkout автоматически выбран проект `E-DEVGAME-MessControl`. Проверяй имя через `list_projects`: у codebase-memory watcher привязан к автоматически выбранному проекту, а дополнительный индекс того же пути с другим `name` может остаться без автообновления. При ручном `index_repository` не задавай отдельное имя.

Сервер ассетов проверяет сохранённые файлы каждые 10 секунд и ждёт два стабильных наблюдения перед экспортом. Каталог включает все `/Game` ассеты и зависимости пакетов. Подробные снимки обновляются для уже экспортированных ассетов; новый ассет выгружается по запросу `asset_read`. Поиск содержимого неэкспортированного ассета ограничен метаданными каталога.

Изменение исходников C++, Build.cs, конфигурации или плагина инвалидирует снимки, даже если `.uasset` прежний. Также проверяются хеши транзитивных `/Game` зависимостей: например, изменение родительского Blueprint инвалидирует значения дочернего CDO. Хеши DLL дополнительно проверяют актуальность сборки. Фоновый watcher не пересобирает проект во время редактирования. Явный `asset_refresh(build=true)` запускает сборку, экспорт и проверку, что код, ассеты и их зависимости не изменились во время операции. Файловая блокировка защищает от двух одновременных экспортеров; запись SQLite транзакционная.

Несколько MCP-подключений могут дождаться одного активного экспорта через его `job_id`. Новые запросы не объединяются с ним: после завершения повтори запрос нужных ассетов. История завершённых заданий сохраняется в `Saved/ProjectIndex/jobs`; их статус остаётся доступен после следующего обновления и перезапуска сервера.

```powershell
python Tools/ProjectIndex/index.py status
python Tools/ProjectIndex/index.py refresh --asset /Game/Data/DA_Equipment.DA_Equipment
python Tools/ProjectIndex/index.py refresh --all
python Tools/ProjectIndex/index.py read --asset /Game/Data/DA_Equipment.DA_Equipment --section properties
python Tools/ProjectIndex/index.py references --query UMCEquipmentProfile
python -m unittest discover -s Tools/ProjectIndex -p 'test_*.py' -v
```

По умолчанию первый refresh подробно экспортирует DA_Equipment, WBP_GameplayHUD и NS_BrushFoam. `--all` выгружает весь каталог; последующие refresh обновляют устаревшие снимки. Для полного анализа перед большим рефакторингом используй `--all` / `asset_refresh(export_all=true)` и дождись завершения.

## Что доступно

`asset_read` поддерживает `summary`, `properties`, `class_defaults`, `graphs`, `subobjects`, `data_table`. Граф содержит классы и заголовки узлов, GUID, пины, типы, значения и соединения. Для Blueprint-вызовов сохраняются пути UFunction и соответствующие C++-имена. Niagara-графы и stateless-модули выгружаются из объектов сохранённого пакета. Data Assets содержат эффективные отражаемые значения; Blueprint — также значения CDO. DataTable содержит строки и тип структуры.

`asset_references` связывает ассеты с пакетами, объектами, классами и функциями. Это отдельный индекс, не импорт произвольных связей в базу codebase-memory. Для совместного анализа агент запрашивает оба MCP. Результаты содержат тип доказательства и актуальность; отсутствие ссылки не доказывает отсутствие всех использований.

## Ограничения

Даже codebase-memory 0.11.0 частично разбирает Unreal-макросы: в первой проверке 59 файлов получили `parse_partial`, а класс с `MESSCONTROL_API` в заголовке мог быть представлен как функция. Поэтому перед изменениями проверяй `check_index_coverage` и исходные объявления; отсутствие класса/вызова в графе не доказывает его отсутствие в проекте. Индекс ассетов дополнительно даёт точные пути отражаемых классов, Blueprint parent class и ссылки на функции.

Читается сохранённое состояние. Несохранённые редакторские правки и визуальный результат проверяются через UE. Экспорт не сохраняет, не компилирует и не изменяет исходные пакеты. Native-поля вне reflection, runtime-состояние, внешние графы `/Engine` и `/Niagara` и бинарные данные мешей/текстур не декодируются. Коллекции более 256 элементов и текст более 32768 символов ограничиваются с диагностикой. Пагинация MCP ограничивает размер ответа; большие графы и наборы под-объектов читай по страницам.

Снимки, SQLite, build stamp, запросы и журналы находятся в `Saved/ProjectIndex` и игнорируются Git. `stamp-build` — служебная команда: вызывай её только после подтверждённой успешной сборки; обычный refresh сам собирает и записывает отметку.

Некоторые временные копии карт могут попадать в Asset Registry, но не загружаться как самостоятельные ассеты. Такие ошибки сохраняются для конкретного пути; успешные выгрузки других ассетов остаются доступны. В первой полной выгрузке не загрузились `/Game/_CodexMapMerge/Base.L_Mouth` и `/Game/_CodexMapMerge/Remote.L_Mouth`; исходные файлы не изменялись и не удалялись.
