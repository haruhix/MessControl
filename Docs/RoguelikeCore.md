# Рогалик: навыки, пассивные эффекты и награды

Дата: **27.10.2026**. Редакция: **0.1**.

Статус: целевой контракт следующей итерации, согласуемый с пользователем. Документ фиксирует решения и открытые вопросы; он не означает, что описанная база уже реализована. Текущее поведение подтверждают исходники, сохранённые Unreal-пакеты и отчёты проверок. Старый технический справочник — [Roguelike.md](Roguelike.md).

Этот документ — точка входа для будущего изменения правил. Поля общего каталога, выдача наград, покупки, ввод и HUD должны соответствовать одному контракту. Реализацию и статус проверки обновлять здесь после интеграции.

## 1. Принятая модель

| Часть | Правило |
|---|---|
| Активные навыки | Четыре слота на `1 / 2 / 3 / 4` |
| Расходники | Занимают те же четыре активных слота; числа `2/3` в референсе обозначают заряды |
| Пассивки | Отдельный набор бафов; активные слоты не занимают |
| Совместная работа пассивок | Разные пассивки работают одновременно. Повтор одного ID не даёт уровни или усиление ×2/×3 |
| Инструменты | Переключаются колесом. Редкая улучшенная версия заменяет соответствующий стандартный инструмент по существующей механике |
| Источники редких инструментов | Магазин и сундуки; редкое получение. Активный слот и место пассивки не расходуются |
| Слот-машина / гриль | Только монеты. Новые роллы не выдают навыки, расходники, инструменты или косметику |
| Визуал интерфейса | Полный дизайн — отдельная задача. В этой итерации нужны функциональные индикаторы в текущем HUD |

Предыдущее предложение «четыре общих слота для пассивных и активных» отменено последним уточнением пользователя. Оно не должно попасть в реализацию или миграцию.

## 2. Пассивки и их источники

- Пассивки продаются в магазине и выдаются из сундуков.
- У магазина заданный ассортимент пассивок, максимум четыре позиции. Это не автоматически равнозначно четырём покупкам за ран.
- Для представления бафов нужно предусмотреть ожидаемый состав **четыре из хаба + четыре за ран**, то есть восемь разных пассивных эффектов. Пользователь подтвердил: **восемь — только ориентир для HUD, а не жёсткий gameplay-лимит**. Типов источника два — магазин хаба и сундук рана.
- До утверждения лимитов интерфейс не должен скрывать лишние реальные бафы или вводить собственный предел выдачи.
- Принадлежность пассивки проверяется по общему ID. Установленная пассивка исключается из новых предложений и повторных покупок этого игрока. Это не запрещает получить её другому игроку.
- Категории «Бой», «Выживание», «Еда», «Уборка», «Спрей» — метаданные каталога, а не выделенные слоты.
- Наличие разных пассивок не означает бесконтрольное сложение всех чисел. Правила сочетания модификаторов фиксируются для каждого эффекта на этапе реализации навыков.

Нужно хранить источник получения вместе с ID: покупка в хабе / сундук рана, ID выдачи и принадлежность рану. Это позволит считать источники и менять баланс, не восстанавливая их по тексту названия.

## 3. Четыре активных слота

- Слот содержит один активный навык или один расходник. Несколько зарядов расходника остаются одним предметом в одном слоте.
- Повторный ID исключается, пока этот навык или расходник находится в активном наборе игрока. Удалённый при замене ID снова допускается в предложения.
- Полностью потраченный расходник снова допускается в награды: его ID больше не считается имеющимся. Для представления этого состояния предлагается освобождать слот после последнего заряда, не оставляя в нём непригодный предмет.
- Активный навык может иметь кулдаун; расходник — конечные заряды. Способ применения задаётся данными, а не номером слота.
- База должна поддерживать подготовку/прицеливание, подтверждение и отмену. Гранату из референса нельзя заранее свести к мгновенному взрыву по цифре: её конкретный контракт включает подготовку и бросок.
- Момент расходования заряда определяется успешным началом необратимого действия. Для гранаты это может быть извлечение чеки, для другого предмета — подтверждение применения; простое открытие прицела не должно автоматически тратить любой расходник.
- Переключение интерфейса, смерть и смена Pawn должны корректно завершать подготовку. Нельзя бесплатно возвращать уже потраченный заряд или применять эффект повторно.

## 4. Получение, замена и таймер

Сундук и магазин должны обращаться к одной серверной проверке получения. Виджет отображает предложение и отправляет выбор; он не выдаёт награду и не списывает валюту самостоятельно.

### Активный навык / расходник

1. Есть свободный слот: выбрать карточку и установить предмет в свободное место.
2. Все четыре заняты: выбрать карточку, затем заменяемый слот либо пропуск.
3. До подтверждения сохраняется старый набор; в магазине монеты ещё не списываются.
4. Подтверждение атомарно проверяет предложение, текущий набор, отсутствие дубля и баланс, затем выполняет замену и оплату.
5. При полном наборе истечение 40-секундного таймера сундука означает пропуск с сохранением старых слотов. Переход к выбору заменяемого слота не продлевает срок.

### Пассивка

Получение добавляет отдельный баф, а не запускает выбор активного слота. Достижение возможного лимита пассивных источников должно обрабатываться отдельным правилом после утверждения лимитов; нельзя молча заменять активный навык.

### Инструмент

Редкая версия идёт в существующую систему замены соответствующего стандартного инструмента. Она не вызывает экран замены активного слота. Текущую личную/командную принадлежность улучшений нельзя менять незаметно при переносе каталога.

### Общие требования

- У каждого игрока личный выбор; завершение одного не закрывает карточки остальных.
- Пропуск и таймаут — явные исходы выдачи. Ожидание следующего этапа должно завершаться без фиктивного получения предмета.
- При меньшем числе подходящих записей показывать одну или две карточки. Нулевой пул разрешается безопасным завершением выбора, без зависшего сундука.
- Выборка хранится на время предложения: переоткрытие панели или смена зубика не дают бесплатный реролл.
- Устаревший запрос или повторный RPC не должны повторно выдавать награду, снимать монеты или расходовать заряд.
- Прежний случайный автовыбор при наличии свободного активного места и таймаут пассивной награды требуют явного согласования для новой модели. Подтверждённое правило «сохранить старый набор» относится к полным активным слотам.

## 5. Общий каталог

Текущий корень — `/Game/Gameplay/Roguelike/DT_Perks`, строка `FMCPerkDefinition`. Его нужно мигрировать к новому контракту, сохранив один источник определений. Окончательное имя и путь нового asset выбираются при миграции ссылок, а не созданием второго независимого каталога.

Предлагаемые группы данных:

| Данные | Назначение |
|---|---|
| Стабильный ID | Единая ссылка из наград, магазина, состояния игрока и UI |
| Вид записи | Пассивка / активный навык / расходник / замена инструмента |
| Название, описание, иконка | Общая локализованная презентация |
| Категория и редкость | Группировка и правила предложения |
| Доступность и источники | Магазин / сундук; отдельные веса и настройки ассортимента |
| Ссылка на эффект и его параметры | Реальная реализация; описания не исполняются как игровые правила |
| Активация, кулдаун, заряды | Только для соответствующих видов записей |
| Ссылка на улучшенный инструмент | Использует существующие данные инструмента без копирования его мешей/анимаций в строку навыка |

Магазин может иметь отдельные строки ассортимента и цены, сундук — веса пула. Они ссылаются на общий ID и не поддерживают отдельные копии названий, описаний и иконок навыка.

Повтор «Свежая доставка» на исходной схеме — одна запись каталога, если пользователь не задаст два разных эффекта. Конкретные проценты, названия и эффекты схемы реализуются следующим этапом, после базы.

Точные вероятности и распределение редкостей новой модели ещё не утверждены. Старые веса выпадения не становятся согласованным балансом этой итерации автоматически.

## 6. Владельцы состояния и смена зубика

- Состояние принадлежит игроку на `PlayerState`, используя существующую основу `UMCPerkComponent` или её мигрированный вариант.
- Разделяются четыре активных слота, набор уникальных пассивок и существующие улучшения инструментов. Они не считают ёмкость друг друга.
- Смерть и смена зубика сохраняют награды по текущему контракту. Пассивные эффекты корректно отвязываются от прежнего тела и применяются к сменщику ровно один раз.
- Заряды и кулдауны не должны сбрасываться только из-за смены тела или переоткрытия меню.
- Перенос таймеров между мирами должен сохранять оставшееся время; абсолютный `WorldTime` старой карты нельзя без преобразования трактовать как время новой.
- Покупки в хабе предназначены для ближайшего рана. Смерть и смена зубика их сохраняют; после окончания рана навыки сбрасываются, монеты сохраняются. Постоянное владение купленными навыками не вводится.
- Конкретный UX подготовки стартовых активных слотов и перенос прежних ожидающих покупок согласуются при миграции; купленные предметы нельзя молча потерять.

## 7. Интерфейс текущей итерации

- Существующий HUD получает четыре активных индикатора с номером, иконкой, готовностью/кулдауном и зарядами.
- Отдельно выводятся приобретённые пассивные бафы; первоначальный ориентир компоновки — восемь ожидаемых разных эффектов. Возможность расширения не должна требовать изменения gameplay.
- Возможное временное место — рядом с блоком инструмента, как на пользовательском эскизе. Точные размеры, раскладка, новый арт и окончательная анимация относятся к отдельной задаче визуала.
- Сундук и магазин отображают правильный вид записи. Для пассивки — добавление бафа, для активного — установка/замена, для инструмента — замена оружия.
- В модальном выборе цифры работают на интерфейс: существующие 1–3 выбирают карточки, 1–4 могут выбирать место замены. Они не запускают навыки за открытой панелью.
- Колесо остаётся вводом переключения инструментов. Старые привязки цифр к инструментам необходимо действительно снять, а не только добавить рядом новый обработчик.
- Иконки, кисти виджетов и будущие ресурсы навыков должны входить в подготовку каждой использующей их локации. Первый показ карточки не должен впервые загружать известный игровой визуал.

## 8. Что входит в основу

1. Контракт общего каталога и миграция ссылок/ID.
2. Раздельное хранение активных слотов, пассивных бафов и улучшений инструментов.
3. Общая выдача, фильтрация повторов, замена, отказ и безопасное завершение по таймеру.
4. Привязки 1–4, заряды, кулдауны и расширяемый жизненный цикл применения.
5. Функциональные индикаторы в текущем HUD и адаптация текущих карточек сундука/магазина.
6. Монетные награды гриля без выдачи предметов.
7. Сохранение/перенос состояния и минимальные проверки на технических записях.

Реализация полного набора эффектов со схемы, их финальный баланс/VFX/звук и самостоятельный редизайн HUD не входят в этот этап. Наличие записи будущего расходника само по себе не включает ранее отключённую механику кальция или другие незавершённые эффекты.

## 9. Точки миграции текущей реализации

| Текущий путь | Необходимое изменение |
|---|---|
| `MCPerkTypes` / `MCPerkComponent` | Уйти от общего стакового списка и FIFO-очереди к раздельным состояниям; не наращивать уровни одной пассивки |
| `MCStageBoosterRewardChest` | Вместо трёх фиксированных мгновенных бустеров — запись нужного вида и личный исход выдачи/пропуска |
| `MCRewardChest` / `MCRogueOffers` | Общий фильтр, корректные 0/1/2 предложения, отсутствие обхода активных слотов и пассивного владения |
| `MCHubEconomyComponent` / `MCHubShopWidget` | Ассортимент, новые виды покупок и подтверждение; не обрезать молча старую очередь купленных бустеров |
| `MCRogueBoosters` / ввод контроллера | Устранить обход через старую очередь и общую кнопку G при переходе на адресные слоты |
| `MCGameplayHUD` / `MCBoosterWidget` / карточки | Четыре активных состояния плюс отдельные бафы без полного изменения визуального стиля |
| Таблица роллов гриля и старые receipts | Новые роллы только монеты; старые сохранённые предметные результаты требуют явной миграции/компенсации, не скрытого удаления |

Перед заменой row-структуры экспортировать прежние данные и проверить исходные/saved-package ссылки. Существующие монеты, косметику, покупки и улучшения инструментов не терять при миграции. Старые записи/пути удалять только после перевода потребителей.

## 10. Проверка и открытые решения

Основа проверяется на получении и замене четырёх активных предметов, расходовании зарядов, независимых кулдаунах, отдельных разных пассивках, повторных запросах, таймауте полного набора, смене зубика и корректном переходе между локациями. Редкий инструмент не занимает слот навыка; гриль выдаёт только монеты. Проверки реализации фиксируются в [Validation.md](Validation.md), а не объявляются пройденными этим документом.

Открыто:

1. Продаёт ли магазин активные навыки/расходники наряду с пассивками и редкими инструментами?
2. Подготовка стартовых активных слотов и миграция прежних ожидающих покупок без потери предметов.
3. Поведение при нулевом пуле и таймауте пассивной награды. Лимит восемь и счётчики 4+4 не используются как запрет получения.
4. Детальные правила использования каждого активного навыка/расходника и редкости/баланс конкретных инструментов.
