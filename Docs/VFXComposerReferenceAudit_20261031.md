# VFX Composer: сверка с первоисточником

31.10.2026. Первый аудит: основной агент лично просмотрел во встроенном браузере шесть статичных изображений Fab — медиа 1, 2, 4, 5, 7 и 8. Видео тогда не просматривались. Второй аудит: основной агент лично изучил указанные ниже фрагменты оригинального tutorial, его описание и главы. Это целевой просмотр, не утверждение о просмотре всего ролика или всех трёх видео галереи. Панель transcript оставалась на загрузке; расшифровка не использована. Сборка и изменения инструмента в эти проверки не входят.

Источник: [VFX Composer — VFX4GAME](https://www.fab.com/listings/3320d820-f836-4ab3-b67d-3aedcdfdceb5).

## Что видно и чего у нас не хватает

| Область | На изображениях источника | Текущее окно MessControl |
|---|---|---|
| Начало работы | Home с тремя карточками категорий | Сразу рабочая композиция |
| Выбор | Библиотека с категориями, миниатюрами, выбранным элементом и Add to Graph | Выбор NS через Content Browser |
| Композиция | Центральный граф; цветные группы, NE_* с CPU/GPU, соединения к Output | Список отдельных NS |
| Узел | Миниатюра, Solo и Deactivate рядом | Строка списка и Details |
| Preview | Слева; Studio/Dark/Outdoor, масштаб, offset, collision и playback | Большой центральный viewport и нижний таймлайн |
| Preset | Имя, Save, список, Load, Delete, Files | Работа с DA и сохранение новой копии |

Описание автора отдельно заявляет экспорт в Niagara System. На первом, статичном этапе настройки выбранного узла, правила соединений и содержимое Files не были установлены. Ниже перечислено, что действительно добавил просмотр tutorial. Круглая миниатюра сама по себе не доказывает живую симуляцию каждого узла.

Повторный просмотр раздела Included formats на Fab показал заявленные UE 5.0, 5.5 и 5.8. Это уточняет прежний неполный просмотр карточки; установка и реальная совместимость в MessControl не проверены.

## Gap checklist: источник / проверенный MVP / следующий шаг

Здесь «у нас» — ранее собранный и проверенный MVP от 30.10.2026 ([результаты](VFXComposerMVP.md)), а не обещание возможностей новой незавершённой ветки.

| Элемент | Подтверждение в источнике | Что уже проверено у нас | NEXT — ещё требуется |
|---|---|---|---|
| Визуальный выбор | Библиотека → выбранный элемент/preview → Add to Graph | Выбор NS через Content Browser и добавление слоя | Каталог подготовленных элементов, роли/варианты и preview до добавления |
| Свободная композиция | NE-узлы, группы, Output; видны также связи NE → NE | Произвольный список самостоятельных NS, независимые transform/timing/enable/Solo | Рабочий граф и проверяемая семантика связей; сначала установить её, затем реализовывать |
| Художественные inputs | Уточнённый кадр `NE_Explosion_01` показывает шесть controls без Color; Color RGBA встречается у другого элемента | Типизированные Float/Color/Vector/Bool overrides существующих User-параметров | Короткие осмысленные controls, настроенные под конкретный элемент; отсутствующий input не подменять фиктивным полем |
| Предпросмотр/изоляция | Выбор элемента и Solo в tutorial | Изолированный мир, наш зубик, playback/tails и Solo слоя | Маршрут preview элемента → preview общей композиции; пригодность к игровому ракурсу проверять отдельно |
| Группы | Comment color/font/bubbles | Список слоёв | Выбор/перемещение/группировка и настройки визуальных комментариев |
| Сохранение | Preset workflow; Output Name/Duration/Export | Новая DA композиции, повторное открытие; исходные NS сохраняются | Полный UX presets и отдельный безопасный экспорт единой NS с проверкой результата |
| Связь с игрой | По исследованным кадрам не установлена | Runtime API подготовленной композиции; DT/абилки ещё не подключены | Игровое событие → рецепт композиции → произвольные визуальные слои, их inputs и подготовка ресурсов |

Фиксированные `Start / Loop / Impact` могут быть точками вызова от игровой механики. Они не заменяют библиотеку элементов, произвольный состав/тайминг композиции и настройки каждого слоя. Значки/поля «слот» сами по себе не гарантируют работающую привязку mesh/texture/material: она требует реального input или адаптера соответствующего эффекта. Это наш вывод для архитектуры, а не утверждение об исходниках аддона.

## Вывод и критерии следующей реализации

Нынешняя версия — технический просмотрщик композиции, а не готовый аналог этого рабочего процесса. Похожее расположение трёх колонок недостаточно. Сначала нужен маршрут «категория → визуальная библиотека → добавить → выбрать узел → настроить → сохранить».

1. Preview слева, рабочий граф/библиотека в центре, настройки справа. Примерная цель пропорций 30/50/20 — проектное решение, не заявленная характеристика аддона.
2. Библиотека наших ресурсов с настоящими миниатюрами и понятными ролями: лечение, защита, очистка, попадание, след. Не требовать знания пути NS для первого эффекта.
3. Перемещение и масштабирование графа, группировка, выбор, Solo/включение и Output. Подключение/отключение должно менять реальный состав результата; декоративные провода не считаются функциональной реализацией.
4. Короткие художественные ручки выбранного элемента; технические массивы и namespace-поля — расширенные настройки. Ручка появляется только при наличии соответствующего параметра/адаптера.
5. Показать полный проход пользователя на видео, включая повторное открытие сохранённого результата. До этого не называть интерфейс сопоставимым по удобству.
6. Объединение эмиттеров в один NS — отдельный проверяемый этап. Граф поверх отдельных NS не считать доказательством такого экспорта. Уже сохранённые DA должны продолжать открываться.

Это критерии переделки, а не отчёт об их реализации. Новых игровых эффектов или художественного аппрува эта сверка не добавляет.
