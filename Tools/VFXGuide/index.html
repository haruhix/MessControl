Первый эффект: понятные поля вместо строк кода

На вашем скрине — внутренние выражения сложного следа. Для первого урока основной агент сделал отдельный NS_Practice_FoamBasics: обычные Niagara-модули, числовые поля, цвет и кривая. Производственный след не переписан. Этот образец — небольшая неподвижная пена; он не является ground trail или игровым лечением.

/Game/Tests/VFXPractice/Effects/NS_Practice_FoamBasics
  1. Откройте NS_Practice_FoamBasics. В System Overview выберите его эмиттер — появится стек с Emitter Update / Particle Spawn / Particle Update / Render.
  2. В Particle Spawn → Initialize Particle найдите Lifetime. Сравните 1,6 → 0,8 с, не меняя других полей. Верните 1,6. Поле принимает обычное число.
  3. В том же модуле Sprite Size Mode = Random Uniform: сравните Uniform Sprite Size Min / Max = 35 / 65 → 55 / 85. Это случайный размер внутри диапазона, а не два размера одной карточки. Верните исходные числа.
  4. Нажмите цветной прямоугольник Color в Initialize Particle: откроется picker. Попробуйте чуть более мятный цвет, сохранив alpha около 0,55.
  5. В Emitter Update → Spawn Rate сравните 10 → 5 частиц/с. Затем отдельно в Particle Spawn → Shape Location сравните Sphere Radius 22 → 40 см: меняется область рождения, не размер отдельной частицы.
  6. После этих опытов откройте Particle Update → Scale Color → Scale Alpha. Там выбран обычный Float from Curve: правьте точки кривой для появления/затухания, а не текст HLSL. Сначала сохраните кадр исходной кривой.

User Parameters у Basics пусты — это нормально. Здесь специально нет промежуточных User-ручек: первое задание проходит прямо в полях модулей. В будущем вынесем повторно используемые настройки в User Parameters, когда будет понятно, какой вход ими управляется. Если видите float2(…) или normalize(…), проверьте имя вкладки: вы открыли прежний Trail, а не Basics.

Подтверждены сохранение Basics, назначение Practice_01, чистая компиляция без inline HLSL и новый solo-прогон 12/12. Free Play показывает непрерывную пену: bAutoRepeat=false; P/R остаются паузой и сбросом. Это учебная демонстрация полей, не художественный аппрув. Старые записи полигона не являются записью нового Basics.

Следующий шаг: разобрать код на прежнем скрине и User-параметры Trail

/Game/Tests/VFXPractice/Effects/NS_Practice_Trail

Почему NS-default меняется, а площадка выглядит прежней?

NS хранит устройство эффекта и defaults. Actor/component override задаёт значение только для экземпляра. У BP_PracticeStation есть bTrail, bAutoRepeat, RepeatSeconds. Для Trail станция передаёт TrailWidth / TrailLifetime / TrailOpacity / TrailSpawnSpacing в User-параметры, поэтому они перекрывают defaults NS при запуске/сбросе.

TrailSpeed и TrailAmplitude задают движение источника, TrailDirection — его локальное направление, SurfaceNormal — мировую нормаль. R очищает симуляцию выбранной станции и возвращает источник; сохранённые значения NS/карты при этом не откатываются. Изменения instance в PIE обычно исчезают после Stop: переносите полезное значение в edit-world actor или учебный NS явно.

Для упражнений скопированы NS, renderer-материалы, родители material instances и текстуры. Material Functions, Material Parameter Collections и color curves остаются общими read-only зависимостями; общие runtime-ассеты персонажа также не входят в учебную правку. BP_PracticeBootstrap готовит ресурсы до старта lab; после назначения нового NS повторите Play для проверки первого показа. MC.VFXComposer
Сначала смотрите доступность контекста. «Сценарий + редактирование VFX» означает, что есть контекстный сценарий и подключаемый профиль. «Сценарий · VFX-привязка впереди» позволяет смотреть родную механику; назначение новой Niagara этому событию ещё не подключено. 1

Выберите контекст и его событие

Начните с ракетницы и выберите «Выстрел», «Полёт ракеты», «Попадание» или «Завершение». Другие действия показывают собственные события, а не копию четырёх фаз ракетницы. У пассивки это может быть получение урона, завершение уборки или рывок. Если контекст ещё недоступен, справа указана конкретная причина.

2

Попробуйте эффект из общей галереи

Фильтры «Игра» / «Учебные» / «Все» и поиск показывают настоящие NS нашего проекта. В «Все» доступны и исходные проектные системы: каждая остаётся самостоятельным слоем, её не нужно предварительно склеивать в одну NS. Клик карточки — временная проба в выбранном событии; он не меняет черновик или профиль игры.

Наши NS, учебные заготовки и импортированные Niagara examples отличаются от подготовленного asset pack автора Fab. Если достоверного thumbnail нет, карточка показывает значок группы; форму проверяйте воспроизведением. Чужая целая NS не переименовывается в emitter.

3

Добавьте и настройте несколько слоёв

Нажмите «Добавить» или перетащите карточку галереи на нужное событие в центре. Добавится один независимый слой; Ctrl+Z отменяет добавление. Центральный круг выбирает контекст и не принимает эффект вместо события. Выберите слой для изменения его реальных User-параметров, положения и времени.

Двойной клик по слою открывает исходную NS в обычном Niagara Editor. Правки там — отдельное редактирование исходного ассета. «Новая композиция» заменяет состав выбранного события пустым рецептом или шаблоном; Ctrl+Z возвращает прежний черновик. Вспышка / Дым / След / Свечение — технические starters, а не завершённый арт.

4

03 / ОДИН СЛОЙ ЗА РАЗ

Частица сначала живёт.
Потом мы её видим.

System — весь эффект. Emitter — один набор частиц со своим поведением. Module — конкретная операция в стеке. Нажмите на этап, чтобы разобрать наш след.

На каждом шаге эмиттера

Расстояние превращается в отпечатки

Spawn Per Unit считает пройденный путь. У нашего следа он получает скорость из User.Velocity и расстояние между отпечатками из User.SpawnSpacing. В игре неподвижная губка не должна накапливать новую пену.

Найти: Emitter Update → Spawn Per Unit
Менять расстояние — не то же самое, что менять ширину. Для этого следа не добавляем параллельный постоянный Spawn Rate.

Spawn — один раз, Update — каждый шаг

В Particle Spawn задаём исходный возраст, lifetime, положение, ориентацию и размер. В Particle Update меняем значения с течением жизни. Поздний модуль может перезаписать ранний результат: если размер «не слушается», проверьте весь стек.

User-параметр — ручка с проводом

Одного имени в списке мало: значение должно быть связано со входом нужного модуля. В игре часть User-параметров подаёт код. Не переименовывайте их и не меняйте тип без проверки интеграции.

World Space: история остаётся на полу

У Trail Local Space = false. Источник едет дальше, уже рождённые частицы остаются в мире. Нормаль поверхности и направление фиксируются при рождении. Это не система физического прилипания к любой движущейся геометрии.

CPU / GPU: выбор по задаче

Текущий след — stateful CPU, без particle collision и сил. Для его настройки не требуется переключать Sim Target. GPU может подходить массовым поддерживаемым симуляциям, но сам по себе не делает пену красивее; совместимость, bounds и стоимость проверяют отдельно.

Стек и панели: Epic · Niagara Editor UI. Render и материал: Epic · Niagara Renderers.

06 / МАЛЕНЬКИЕ УПРАЖНЕНИЯ

Теперь в настоящем проекте

Одна правка, один короткий сценарий, одна понятная версия. Сначала запишите исходные значения; завершайте с сохранением или осознанным возвратом.

А

Узкий след или широкий?

  1. Откройте карту практики и выберите Practice_02. Откройте назначенный NS_Practice_Trail и найдите связь User.Width.
  2. На actor сравните TrailWidth 60 и 110 при одинаковых Lifetime/Spacing: эти поля перекрывают NS-defaults в станции. Не меняйте материал одновременно.
  3. Сохраните карту. Для изменений графа отдельно проверьте Compile / Niagara Log и сохраните NS. Если preview пустой, сначала диагностика.
  4. Play → выбрать 02 через F3 → одинаковый ракурс; R перезапускает выбранную станцию. Движется учебный источник эффекта.

Смотрите: читается ли мировая история пути, видны ли зубик и пол. Это визуальный источник; ширина следа не изменяет очистку.

Б

Остановиться, а не обрубить

  1. На учебной станции 02 сравните TrailLifetime 0,8 и 2,4 с при остальных одинаковых числах. Посмотрите длину истории и перекрытия.
  2. R — сброс симуляции, поэтому его нельзя считать доказательством мягкого окончания действия. Для текущего повтора источника наблюдайте частицы, которые уже родились.
  3. При отдельной gameplay-интеграции губки нужен полный цикл поездки/схода: новые рождения прекращаются, старая пена доживает. Эта проверка записывается отдельно.

Разделение времени: lifetime частицы ≠ длительность поездки ≠ cooldown. «Complete» даёт существующим частицам закончить жизнь; мгновенное уничтожение компонента может оборвать хвост.

В

Крюк: поддержать действие, сохранить контакт

  1. Откройте NS_Hook_Impact и найдите один короткий акцент. Запишите его lifetime/size до правки.
  2. Сделайте акцент короче или компактнее, сохранив положение контакта. Не меняйте типы TetherStart / TetherEnd у Loop.
  3. Смотрите полный цикл: замах → полёт → контакт/промах → притягивание при контакте → возврат → восстановление.

Если кисть оторвана или предмет проходит сквозь тело: это дефект позы/контакта для исправления. Плотная пена или вспышка не закрывает такую проблему.

Г

Лечение: от заготовки к своему образцу

  1. В Heal Studio открыт NS_Practice_HealSeed — пенная заготовка. Опишите одну главную форму восстановления, её появление/уход и место относительно лица.
  2. Создайте свой NS под /Game/Tests/VFXPractice/Effects либо продублируйте seed. Сначала главная форма, затем одно вторичное движение.
  3. Выберите Practice_03 → PracticeFX → Asset, назначьте свой NS, оставьте bTrail=false. Сохраните NS и карту, повторите Play.
  4. Принесите короткий клип и параметры. Это визуальный образец; подключение к реальному HealApplied/HP выполняется отдельно.

Результат упражнения: собственный учебный NS на зубике-reference, лицо видно, полный цикл читается. Пример CGHOW помогает разбирать слои; стиль выбирайте по задаче наших зубиков.

Учебная проба и игровое действие. На карте практики F3 выбирает площадку, P управляет паузой lab. Для настоящей губки/крюка используется отдельный локальный сценарий арены: F3 → «АКТИВКИ», затем клавиша слота 1–4. Там мир продолжает жить. Визуальная проба сама по себе не подтверждает попадание, очистку или лечение; сетевой тест и Windows build/cook/package — отдельные задачи.

07 / ЭФФЕКТ В ИГРОВЫХ РАМКАХ

Красивый System — часть действия

Нужно ещё знать, кто запускает эффект, откуда приходят поверхность и скорость, когда остановить новые частицы и кому принадлежит хвост. Разбираем нашу цепочку, а не абстрактный заклинатель.

Игровое событие→DT_Perks: EffectClass + Parameters + VFXProfile→Effect: ActionClass→Action: профиль / defaults→NS или композиция NS + User params→Deactivate → хвост → cleanup
Уже в текущем исходнике

Таблица выбирает действие; действие владеет VFX

FMCPerkDefinition содержит EffectClass, числовой Parameters и новый VFXProfile. В UMCActiveSkillPerkEffect есть ActionClass. В AMCActiveSkillAction defaults StartVFX / LoopVFX / ImpactVFX / EndVFX / WarningVFX остаются fallback. У губки отдельно есть SoapTrailVFX.

Код активирует/останавливает компоненты и задаёт типизированные User-параметры; внешний вид остаётся в NS. Некоторые пассивные cues, включая текущее лечение, представлены native-геометрией; новый preview не превращает их автоматически в Niagara.

Игровая привязка отделена от просмотра

VFXProfile ссылается на DA со слотами Start / Loop / Impact / End / Warning и режимами UseDefault / Replace / Disabled. В окне ракетницы показаны четыре реально используемые роли; Warning она не выдаёт, отдельного универсального Trail слота пока нет.

08 / ДИАГНОСТИКА ПО СИМПТОМУ

Ничего не видно — это ещё не причина

Проверяйте по цепочке: рождаются ли частицы → имеют ли размер и alpha → что читает renderer → попадает ли результат в камеру.

Реальный пример Trail: ракурс и контраст фона. Сохранённая preview camera была на Z = −215, pitch = 0, а пена — у Z ≈ 1,5. Новый ракурс (−400, −500, +500), pitch −37,985°, yaw 51,34°, orbit выключен сохранён в ассете. Основной агент лично подтвердил видимую пену. A/B: при белом HDRI Background её почти не различить, при выключенном фоне на сером — видно. Это подтверждение контраста, не доказательство физического перекрытия геометрией. Скрытие HDRI-сферы было transient: после переоткрытия выключите Background или выберите серый preview profile; автосохранение этого переключателя не подтверждено.
Ещё одна проверенная причина: редактор в фоне почти не обновлял preview. Выбор окна через MCP не перевёл системный фокус с Codex на Unreal. При включённом Use Less CPU when in Background первая запись не показывала нормального обновления. После временного отключения основной агент увидел движение пены и затухание; затем исходную настройку восстановил. Сначала активируйте окно Unreal и проверьте Timeline / realtime. Для осознанной параллельной работы можно выключить Editor Preferences → Performance → Use Less CPU when in Background, а после просмотра вернуть привычное значение. Гайд сам настройки редактора не меняет.
Пустой Niagara preview у Trail
  1. Проверьте, что открыт именно NS_Sponge_Trail, эмиттер включён, Timeline идёт, а в Niagara Log нет compile error.
  2. В User Parameters проверьте PreviewMotion = true, PreviewSpeed > 0, Intensity > 0. В asset-preview нет настоящей скорости игрока.
  3. Активируйте окно Unreal на уровне Windows, проверьте tick / Timeline / realtime. При параллельной работе фон может замедляться из-за Editor Preferences → Performance → Use Less CPU when in Background. Меняйте эту настройку осознанно и после проверки возвращайте нужное вам значение.
  4. Перезапустите симуляцию / Reset. Проверьте particle count через доступные отладочные панели.
  5. При count = 0 ищите spawn / lifecycle / связи. При count > 0 — SpriteSize, Color alpha, материал, facing, камеру и bounds.
  6. Для текущего Trail проверьте сохранённый новый ракурс и серый фон: выключение Background может потребоваться снова после переоткрытия. Если симптом другой — сохраните скрин панелей и лог, не объявляйте шейдер сломанным только по пустому виду.
Число меняю, картинка прежняя
  1. Убедитесь, что меняете нужный System/эмиттер и preview перезапустился.
  2. Посмотрите, подключён ли User-параметр к входу. Есть ли clamp, другой параметр или более позднее присваивание?
  3. Particle Spawn меняет будущие частицы; уже рождённые могут хранить старое значение.
  4. В игре проверьте native override / Params строки навыка. Для Trail ключи TrailWidth, TrailLifetime, TrailOpacity, TrailSpawnSpacing могут перекрывать defaults.
В редакторе есть, в игре пропало
  1. Проверьте сохранение нужного пакета и активацию действия.
  2. Для Trail требуется поддерживаемая поверхность и движение; в игре PreviewMotion выключен специально.
  3. Посмотрите реальное положение, ориентацию, bounds, renderer/material и условия culling/Effect Type.
  4. Проверьте, достижим ли ресурс из preload roots нужной локации. Для нового ассета это часть интеграции.
  5. Сравнивайте с обычной камерой/светом L_Mouth, а не только с пустой preview-сценой.
Первый показ серый или с задержкой
  1. Запишите именно первое появление и время в логе; не скрывайте симптом повторным запуском.
  2. Проверьте цепочку NS → renderer material → texture и отражённые ссылки/manifest для этой карты.
  3. Известные динамические варианты готовят до readiness barrier. Одного нуля global jobs недостаточно для deferred material / Niagara VM requests.
  4. Отделяйте Editor shader readiness от packaged PSO/resource preparation. Тёплый локальный запуск не доказывает холодный запуск пакета.
След ездит за губкой или обрывается
  1. Для истории на полу проверьте Local Space = false. При local-пространстве старые частицы могут ехать вместе с источником.
  2. Проверьте, не переписывается ли Position каждый Update положением владельца.
  3. При сходе действие должно прекратить spawn и дать хвосту затухнуть. Нужны корректные Deactivate / Complete и время жизни владельца компонента.
  4. Прыжок/разрыв поверхности не должен соединяться длинной полосой. Это отдельная проверка интеграции движения.
Красиво близко, шумно из игровой камеры
  1. Верните обычные дистанцию, свет и фон арены. Оцените силуэт зубика и читаемость еды.
  2. Уберите по одному вторичные слои, уменьшите ширину/длительность, затем сравните.
  3. Измеряйте прозрачные перекрытия и render cost отдельно от числа частиц; FPS на одном эффекте не гарантирует бюджет.
  4. Проверьте хват и полный цикл действия. Кисти должны иметь явную роль и устойчивый контакт, предмет — восстановиться после завершения/прерывания.
